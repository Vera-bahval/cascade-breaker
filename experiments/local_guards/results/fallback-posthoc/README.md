# Jev → сохранённый LLM: предварительный post-hoc replay

176/176 основных P4-префиксов точно соединены с архивом коллег по episode_id и context_seq=cut_seq. Для каждого имеются V3/V4 и четыре вероятности SecJev0.8B. Никаких новых API-запросов, обучения или изменения старых результатов.

Исследуемая эвристика: уверенность = минимум по четырём вопросам max(p,1-p). Если уверенность ниже порога, используется сохранённый вердикт LLM. Иначе Jev запрещает при любом p>=0.5, разрешает при всех p<0.5. Это новая описательная агрегация атомарных вопросов, не откалиброванная вероятность вреда. Пороги не объявляются независимо проверенными.

Оба сохранённых fallback-верификатора дают одинаковые итоговые счётчики в этой таблице. При0.99 Jev самостоятельно решает15 случаев, все15 совпадают с соответствующим LLM и метками; это наблюдение на знакомом архиве, не гарантия. При0.8 у дешёвых108 решений18 ошибок относительно меток.

Средняя сохранённая стоимость текущего Jev extraction по176 строкам около19.87с (не медиана; кешированные/восстановленные reference timings включены). Средняя записанная задержка P4-LLM: V3≈1.03с, V4≈1.19с. Сумма этих времен — реконструкция разных запусков/оборудования, не живое end-to-end измерение. В текущем локальном runtime ускорение такой схемой не продемонстрировано. Сокращение числа LLM-вызовов не равно сокращению общей задержки или денежной стоимости; локальная цена Jev неизвестна.

У компонентов разные prompts/evidence. P4-вердикт сравнивается с episode-level observed harm label; это основной архивный протокол, не локальная adjudication каждого действия. Ранние остановки на других этапах не моделируются. На шести новых независимых семействах вердиктов LLM коллег нет, поэтому такой внешний replay пока невозможен.
