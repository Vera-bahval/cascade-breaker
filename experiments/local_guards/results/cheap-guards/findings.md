# Главная находка — эффект протокола калибровки

Полная основная серия завершена: 176 P4-префиксов, все пять блоков, 31 непустая комбинация × два варианта табличных признаков × три rules-варианта; с диагностикой и контролями — 81 конфигурация и 747 полных seed×arm оценок. Ошибок обучения и UNKNOWN нет. Предел внутреннего episode FPR — 5%, измеренный максимум — 4,762%.

В исходном протоколе ни одна новая комбинация с R1 не превысила 78/83 опасных продолжений. Но это нельзя объявлять провалом семантических признаков: все пять пропусков R1 принадлежат одной группе authority injection. Когда эта группа удержана во внешнем fold2, rules ловят все опасные обучающие случаи. Критерий «максимум обнаружения, затем минимум ложных STOP, затем самый высокий порог» выключает каждый дополнительный детектор: 243/243 фиксированных learned+R1 порогов в этом fold равны бесконечности. Его оценки на новой группе уже не влияют на решение. Группа содержит десять опасных эпизодов; R1 пропускает пять из них.

Пересчёт 4B по тому же протоколу подтвердил ограничение: все 4B+R1 варианты также получают 78/83. Следовательно, прежние исторические 83/83 у 4B нельзя напрямую противопоставлять новым 78/83. Исторический evaluator выбирал самый низкий допустимый порог, новая серия — самый высокий при равной полезности. Даже у 0.8B скалярные оценки побитно совпадают, а отличие ложных остановок объясняется порогами, не случайностью модели. Основные результаты сохранены; matched-контроль выполнен отдельно по кешу, без inference.

# Отдельная post-hoc диагностика протокола

До её вычисления зафиксирован отдельный план: взять уже сохранённые решения компонента с порогом, выбранным внутри обучения БЕЗ rules, и объединить их с R1. Никакого нового обучения, inference, поиска порогов или выбора победителя по внешним результатам. Это исследовательская диагностика после просмотра основной серии, а не её подтверждающая замена. Числа — seeds 17/29/43.

| Вариант при независимой калибровке компонента, затем OR R1 | Опасные STOP /83 | Безопасные STOP /131 |
|---|---:|---:|
| R1 | 78 / 78 / 78 | 0 / 0 / 0 |
| Jev 0.8B: текущие четыре оценки + CatBoost | 80 / 82 / 80 | 4 / 7 / 5 |
| Jev 0.8B: 16 оценок напрямую + CatBoost | 81 / 78 / 79 | 5 / 3 / 5 |
| Prompt Guard 22M + CatBoost | 79 / 81 / 83 | 6 / 5 / 7 |
| Prompt Guard 86M + CatBoost | 78 / 78 / 78 | 6 / 3 / 9 |
| NLI + CatBoost | 78 / 78 / 81 | 0 / 0 / 2 |
| MiniCheck + CatBoost | 78 / 78 / 78 | 3 / 16 / 16 |
| Дешёвая комбинация, выбранная внутри обучения без R1 | 78 / 78 / 78 | 3 / 2 / 4 |
| 4B: скаляр, формат выбран внутри обучения | 83 / 83 / 83 | 3 / 2 / 3 |
| 4B: CatBoost, формат выбран внутри обучения | 79 / 81 / 83 | 0 / 1 / 1 |

У дешёвых признаков есть добавочный сигнал, скрытый совместной калибровкой. Однако независимая схема не даёт устойчивого преимущества 16 исторических оценок над четырьмя текущими, а выбор комбинации по общей обучающей полезности не выбирает лучшую защиту от единственной новой группы. Среди показанных вариантов 4B-скаляр — более устойчивый семантический ориентир этого пилота; это сравнение вариантов защитника, не доказательство причинного эффекта размера модели. Внешний FPR некоторых дешёвых вариантов превышает внутренний целевой предел: например, 7/131 = 5,34% у PG22. Гарантии переноса порога нет.

# Задержка и ресурсы

Prompt Guard действительно быстр: PG22 p50/p95 извлечения признаков 0,056/0,112 с, PG86 — 0,074/0,107 с. Оба checkpoint получены с ModelScope: веса, конфигурации, токенизаторы и документы совпали с закреплёнными официальными Git/LFS-идентификаторами Meta. Фактические полные числа параметров — 70,83 и 278,81 млн; 22M/86M оставлены как названия моделей. Все модели FP32; CPU/MPS и три A/A повтора прошли.

Jev: p50 текущего этапа — 1,832 с, четырёх этапов — 6,521 с; это реконструкция прежних затрат, не новый inference. Чтение кеша измерено отдельно. Само объединение последовательности не делает мониторинг бесплатным.

NLI/MiniCheck в полном режиме проверяют четыре утверждения, объяснение и несколько источников: p50 7,759 и 18,588 с. Минимальный скалярный режим четырёх утверждений против trusted_combined дешевле — p50/p95 1,045/1,410 и 2,663/3,150 с. Он точно совпадает с исходным скаляром на всех 176 примерах, но не даёт новых обнаружений поверх R1. Это результат замороженных вопросов и JSON-свидетельств; другая постановка NLI не проверялась.

# Перенос и ограничения

На известном raw64 стресс-тесте R1 обнаруживает 25/32 опасных случаев без ложных остановок, R2 — 29/32 без ложных остановок. Исходная архивно выбранная raw-совместимая комбинация + R1 получает 28/27/28, но останавливает 2/32 допустимых случая. После независимой калибровки фиксированный PG22 + CatBoost + R1 даёт 28/32 и 2/32 во всех seeds. У NLI эта схема в двух seeds останавливает все 32 допустимых случая. Устойчивый перенос не подтверждён. Отсутствующие Jev checkpoints и табличные поля не заполнялись искусственно; недоступные победители указаны явно. 4B на raw64 в этой серии не запускался.

Rules_v2 даёт 83/83 и 0/131 на основном архиве, но разрабатывался с его учётом. Добавленный learned-компонент при совместной калибровке ничего не меняет. R1/R2 сохраняют 61/98 корректных исходно честных платежей; уже созданные опасные состояния и восстановление честных задач этим P4-сравнением не исправляются.

Следующий научный шаг — заранее определить, должен ли контроль сохранять чувствительность к неизвестным группам при отсутствии добавочных положительных примеров в обучении, и проверить эту политику на новых семействах и независимых траекториях. Подбирать её по текущему внешнему результату как подтверждающий эксперимент нельзя.

Это архивный контрфактический STOP до вредного перевода, не предотвращение вживую. Три seed используют одни эпизоды; raw64 уже известен и не является независимым подтверждением. Платные inference API не использовались; денежная стоимость локального исполнения и подписочные кредиты не вычислялись. Основные проверки: 220 passed, 1 skipped, 36 subtests passed; matched-контроль — ещё 5 тестов, диагностика протокола — ещё 6. Исходные артефакты и разметка сохранены.
