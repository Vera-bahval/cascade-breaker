# Independent synthetic extended-policy screening set

This is an offline state-machine benchmark. No LLM/API/payment execution is used. It contains six mechanisms, twenty independently keyed paired templates per mechanism, two counterfactual variants per template, 240 episodes total. Twenty templates mean five causal intervention axes crossed with four independently keyed layouts, not twenty distinct mechanisms. One group includes both variants. This is exploratory screening, not a 5% false-interruption certification; pair dependence and shared mechanism ancestors limit inference.

`observations.jsonl` contains observable native snapshots and a proposed transfer, with a single identical versioned six-clause extension policy in every episode. `labels.jsonl` is separate. `family`, `group_id`, episode/checkpoint identifiers and sequence positions are metadata and must not become model features. Preserve the equality and inequality of native identity fields through a consistent opaque alias mapping. No family-specific label, oracle verdict, stop flag or hidden backend commit state is an observation.

The primary label is `contract_requires_intervention`, evaluated at P4 by an executable observation-only contract oracle. It is a policy intervention target, not observed monetary harm. `policy_correct_input` is its complement. The historical-harm aliases (`strict_harm`, `harm_if_continue`, `source_benign`, `baseline_paid`, `strict_harm_seq`) are deliberately null: they must not silently become false or be pooled with archive harm calibration/probability metrics.

A separate deterministic forward backend supplies diagnostic `status`, `money_effect_count` and `harmful_effect_if_executed`. The backend enforces its observed CAS/idempotency capabilities and otherwise posts one proposed transfer. A second independently implemented contract checker tests the resulting new effect. Rejected conflicts and confirmed old-commit replays create zero new effects, despite a possible intervention label. A same-key timeout with no definitive reconciliation has an unknown new-effect count, not an invented hidden commit. A fresh-key retry may create one new effect without asserting whether a prior hidden transfer exists. Diagnostic harmful effect means a modeled new transfer violates the explicit extended contract, not a measured loss or a proven duplicate. Null means unmodeled/indeterminate. Nothing in this set is live FinBot execution evidence.

Four cumulative native snapshots align with process positions: P1 after invoice processing, P2 after fraud review, P3 before payments, P4 immediately before transfer. They are synthetic native observations, not generated LLM trajectories. The proposed action is null through P3. Native version mutations have observed timestamps later than prior validation; P4 sees the latest records. Event payload updates replay exactly into the snapshots. Unobserved and inapplicable values are explicit null. No future decision fact is exposed earlier.

The full contract supersedes the old exact-original-amount/one-transfer clauses with exact outstanding obligations and legitimate multiple settlements. All other base policy conditions are checked. All six extension requirements are present and enforced in every case. All unrelated evidence is valid by construction. Native posted ledger receipts are authoritative; adjustment signatures are verified at admission. Budget ledgers use one currency; observed signed FX converts a cross-currency proposal. Exact Decimal arithmetic is used, with no rounding tolerance. The set does not claim support for arbitrary mixed-currency ledger conversion.

The generator and policy/schema were frozen in `generation-freeze.json` before final cases were materialized. The manifest hashes the generator and all data files. It refuses overwrite. Generator/oracle tests use an excluded pilot seed and never read model outputs or hidden labels. Author inputs were the six-family section of the independent review and frozen FinBot policy, not classifier code, scores, old case rows, or model results. A source reviewer audited oracle/contracts and the modeled backend before generation. Mechanism overlap against all historical cases is a separate audit; novelty is not established by this README.
