# Что изменилось после независимого ревью

Это **post-hoc** исследование чувствительности к пороговой политике. Исходная серия не переписана, её первичный вывод не заменяется новой «победившей» строкой. Ни платного API, ни нового inference SecJev/Prompt Guard/NLI/MiniCheck не было. Недостающие внутренние прогнозы 4B и сопоставимый TF-IDF-контроль восстановлены локальным обучением на прежних входах; это новые fit, а не новые траектории FinBot.

1. **Потолок 78/83 объясняется задачей калибровки.** В обучающей части критического holdout rules уже закрывали весь наблюдаемый вред. A закономерно выключала модельный компонент порогом +∞: он не добавлял TP внутри обучения. Это не программная ошибка и не свидетельство бесполезности его признаков на новом механизме.
2. **Политика порога меняет результат на тех же оценках.** Для комбинации дешёвых блоков, выбранной только внутри обучения, с R1: A даёт TP 78/78/78 и FP 5/3/3; C — TP 79/81/83 и FP 6/5/7. Здесь и далее порядок seeds 17/29/43; TP из 83, FP из 131. Внешние 7/131 = 5,34% показывают, что внутренний бюджет 5% не гарантирует внешнего соблюдения.
3. **4B имеет полезный сигнал в этом архиве.** Самостоятельно откалиброванный скалярный 4B с выбором формата по wrapped inner решению (B2) и R1 даёт 83/83 при 2/131 ложных остановках во всех трёх переразбиениях. Та же head при C даёт 83/83 с 6/131. CatBoost на 4B и табличных признаках, C: 83/83 и 3/131 во всех seeds. Это разные исследовательские варианты; они не выбраны по независимому тесту и не доказывают преимущество размера модели как причинного фактора.
4. **У B два уровня выбора.** Fixed B калибрует компонент отдельно и не ограничивает FPR всей OR-системы. B2 выбирает комбинацию по итоговому inner решению; Blegacy сохраняет прежний standalone winner, добавляя rules после выбора. Их нельзя сливать: дешёвый B2+R1 даёт TP 78/78/78, FP 6/4/3; Blegacy — TP 78/78/78, FP 3/2/4. Выбор конфигурации и выбор порога показаны отдельно.
5. **Исправлен реальный крайний случай сетки.** Историческая сетка `nextafter(score, -∞)` с `≥` может пропускать достижимое решение при соседних float-значениях. Новая сетка использует точные уникальные score и +∞; добавлены проверки. Исторический A воспроизведён отдельно; на фактических главных данных исправление не изменило ни одного outer решения. Улучшения C вызваны иной политикой выбора, а не исправлением этой границы.

Все пять опасных продолжений, которые пропускает R1, принадлежат **одной** authority-группе. В этой группе десять опасных эпизодов, пять уже закрыты rules. Поэтому дополнительное обнаружение пяти эпизодов — один новый для holdout механизм, а не пять независимых подтверждений переноса. Три seed повторяют тот же архив. Rules_v2 ранее разрабатывались под этот архив и имеют отдельный статус; их 83/83 здесь не являются доказательством обобщения.

Динамика 0.8B, Prompt Guard 22M/86M, NLI, MiniCheck, их комбинации, табличные LR/CatBoost, TF-IDF и 4B присутствуют в подробных таблицах. Совместное добавление признаков не следует считать автоматически полезным: смотреть нужно парные fixed-method строки и затем отдельно результат train-only выбора. Латентность в CSV — реконструкция прежней стоимости признаков с решением, а не новый живой замер. Старый live LLM-защитник не имеет сопоставимого сохранённого risk/inner-CV набора и в это сравнение порогов не включён.

Восстановлен и исходный LR semantic stack: табличные признаки плюс четыре оценки 0.8B. Для train-only выбора формата с R1 политика A даёт TP 78/78/78 при FP 2/0/12; C — TP 78/83/78 при FP 3/10/12. Это ещё один пример нестабильности на групповых holdout: внутренний бюджет не исключает большого внешнего числа ложных остановок.

Известный raw64 подчёркивает границы переноса: выбранная внутри архива доступная raw64-комбинация с R1 даёт A 28/27/28 опасных STOP из 32 при 2 допустимых STOP из 32; B2 и C — 28/28/28 при тех же 2. Но фиксированный CatBoost на NLI с R1 и C останавливает все 32 опасных **и все 32 допустимых** случая во всех seeds. Это провал специфичности, а не успешная защита. Недостающие четыре checkpoint Jev, исходные табличные поля и raw64-оценки 4B отмечены unsupported; raw64 не подстраивает пороги.

Следующий независимый тест должен различать новые причинные механизмы: валюту/единицы, совокупный лимит, неопределённый commit, расхождение версий проверки и действия, область действия разрешения и частичное погашение обязательств. Независимый ревьюер предложил 240 причинно парных эпизодов как screening, с executable oracle и новыми scenario contracts. Это **проект следующего эксперимента**, он ещё не проведён; для квалификации низкого FPR нужна отдельная заранее закрытая выборка.
