# Ночная серия SecJev 4B

Эта серия дополняет прежний пилот, не заменяет исходную разметку и frozen artifacts.
Общий deadline и checksum неизменяемых входов находятся в `results/night-4b/run.json`.
Новая таблица: `reports/night-report.html`; основной отчёт содержит ссылку на неё.

## Воспроизведение локальной части

Из корня проекта:

```sh
python3 experiments/local_guards/scripts/bootstrap_secjev4b.py --help
python3 experiments/local_guards/scripts/run_secjev4b_pipeline.py --help
```

Использовать точные аргументы из `results/night-4b/runtime/README.md`. Pipeline
проверяет CPU/MPS на шести фиксированных входах и выполняет текущий формат прежде
двух новых. Сохраняет результаты по мере выполнения; повторный запуск продолжает
совместимый checkpoint. Deadline задаётся явно, а не сбрасывается при возобновлении.
Во время CPU/MPS probe и замеров другие модели не должны быть загружены.

Для этой машины выбран MPS FP32 с `question_microbatch_size=1`: четыре вопроса
обрабатываются последовательно, кеш аллокатора освобождается между ними.
Батч из четырёх вопросов создавал сильное давление на общую память и нестабильную
задержку; его исходники и замеры сохранены отдельно в runtime. Новый MPS-режим
проверяется против того же CPU-эталона с четырьмя вопросами в батче. Это изменение
исполнения, не весов, точности параметров, вопросов или контекста. Для Metal нужен
доступ к GPU с хоста: внутри ограниченного sandbox `mps.is_available()` был false.

`scripts/finish_night4b.py` — отдельный локальный завершитель. Он ждёт успешного
окончания model pipeline, затем последовательно выполняет ML, тесты, manifest
исходников и HTML. Он не вызывает inference API и не повторяет скрытую оценку
rules. При остановке численной проверки требуется диагностика; завершитель
не заменяет устройство и не запускает скрытые повторные серии.

Входы форматов заморожены в `results/night-4b/formats/inputs.jsonl`. Исходный
первый вариант сохранён как superseded-before-inference; окончательная версия
не подбиралась по ответам 4B. Structured facts-only — абляция содержания, а не
обещание меньшего числа токенов. История меняет и содержание, и применимость
вопросов, поэтому результат не изолирует эффект сериализации.

```sh
PYTHONPATH=experiments/local_guards experiments/local_guards/.venv/bin/python \
  -m cascade_guard.night_ml \
  --scores experiments/local_guards/results/night-4b/scores.jsonl
```

Порог и формат выбираются внутри группового обучения. В отчёте разделены все
безопасные продолжения (131), безопасные продолжения, достигшие P4 (93), прежняя
eligible-популяция (98) и исходно честные задачи (тоже 98, но другой состав).
Отсутствие P4 не является успешным завершением исходной задачи.
Три seed повторно делят те же эпизоды: их результаты нельзя суммировать как
независимые наблюдения или использовать для подтверждения FPR ниже 1%.

## Rules и стоимость

Разработчик стартовал с отдельным контекстом после заморозки 64 скрытых
синтетических случаев. Только одна итоговая оценка проведена после freeze кода.
Повторять hidden evaluation для подбора правил нельзя. Архивная оценка остаётся
ретроспективной; пять дополнительных обнаружений в одном семействе не доказывают
перенос на новые семейства атак. Случай successful-only Fraud — отдельная политика.

`rules-cost.json` содержит реальные накопительные счётчики отдельных сессий.
Cached input входит в input, reasoning входит в output: повторно их не прибавлять.
Development и независимая оценка показаны раздельно; orchestration не имеет точной
атрибуции. `rules-runtime-end-to-end.json` измеряет enrichment вместе с decision,
а не только готовый нормализованный вход. Доверенная registry evidence в будущем
требует привязки к invoice со стороны адаптера; такой live registry этой серией
не реализуется. Уже установленный HOLD не снимается словами модели.

Изначальные hidden64 проверяют нормализованный контракт: признаки доверия уже
поданы на вход. Отдельная дополнительная слепая raw64-диагностика заморожена
новым агентом до импорта неизменённого кода. Она проверяет извлечение из сырых
событий вместе с решением, сохраняя исходные вычисленные признаки суммы и счёта.
Результат 29/32 опасных и 0/32 ложных остановок; три пропуска — перефразированные
ссылки на разрешение руководства. Это posthoc stress test, не новая независимая
выборка реальных задач. Код не дорабатывался после раскрытия ошибок. Его
результаты и стоимость аудитора приведены отдельно от исходной оценки.

Метаданные стоимости можно пересобрать без повторной оценки fixtures:

```sh
PYTHONPATH=experiments/local_guards experiments/local_guards/.venv-finbot/bin/python \
  -m cascade_guard.night_rules_cost --workspace experiments/local_guards \
  --developer-session /path/to/developer-session.jsonl \
  --evaluator-session /path/to/independent-evaluator-session.jsonl \
  --raw-auditor-session /path/to/raw-auditor-session.jsonl
```

Session JSONL остаются локальными: считываются только счётчики токенов и модель.
Последний счётчик накопительный; складывать события счётчиков между собой нельзя.

## Luna

Повторный showcase хранится в `results/luna-showcase-night`; первоначальная
неуспешная серия сохранена отдельно. Только шесть эпизодов, отдельная БД на каждый,
smoke и прекращение всей серии при первом failed workflow. Прежние detector и
threshold сохраняются: новые 4B/rules не подменяют этот интеграционный контроль.
Параметры и политика расхода приведены в `SHOWCASE.md`. Запуск требует настоящего
подтверждения settings не старше часа. Повтор этой API-серии не является частью
локальной команды воспроизведения и не должен происходить автоматически.

## Обновление отчёта и проверки

```sh
PYTHONPATH=experiments/local_guards experiments/local_guards/.venv-finbot/bin/python \
  -m cascade_guard.night_report
cd experiments/local_guards
.venv-finbot/bin/python -m pytest tests --junitxml=results/night-4b/tests.xml
```

HTML формируется только из сохранённых результатов. Отсутствующие этапы явно
обозначаются; незавершённый набор scores не превращается в полную оценку.

В этой серии первый запуск общих тестов из корня workspace дал четыре
FileNotFoundError для относительных fixtures. Исправлен cwd тестового процесса.
Первый финализатор сохранён в `finalizer-attempt-1.json`, его лог не удалён.
`scripts/finish_night4b.py --resume-postprocessing` проверяет checksum завершённой
ML-оценки и переиспользует её, затем запускает проверки и сборку отчёта.
Успешный inference/ML при этом не повторяется. Итог: 120 passed, 1 skipped.
