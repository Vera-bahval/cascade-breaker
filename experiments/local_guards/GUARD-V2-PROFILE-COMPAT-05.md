# Frozen head profiler caller compatibility 05

The original archive profiler failed during its first joblib load before writing profile.json. Frozen heads were serialized by `python -m cascade_guard.v2_eval`, which records the top-level wrapper class as `__main__.Model`. Running the different profiler module as `__main__` cannot resolve that class. The preserved driver log is pinned as failure evidence.

The new caller installs exactly `__main__.Model = cascade_guard.v2_eval.Model` for the original frozen profiler `run()` call, restoring the prior binding in finally. It verifies the canonical class comes from the frozen evaluator source; the top-level custom-class inventory is Model and RuleMap. Model is the serialized fitted-head wrapper. RuleMap is an ephemeral rules flag dictionary, not part of the serialized Model fields or estimators; no RuleMap alias is introduced. This is a module-resolution alias to the same class object and code, with no scientific changes, fitting, model rewrite, threshold changes, prediction artifact changes or hidden observations.

Original authorization, source pins, COMPLETE, diagnostic/profile protocol and frozen validate_completion/run integrity checks remain active. An independent JSON source freeze pins this caller, public tests, this text, the completed root marker, original profiler protocol and preserved failure log. The root launcher pins the JSON protocol SHA. Frozen global deadline stays unchanged and the caller adds a process alarm at that deadline. The original archive profiler's max_seconds, sampling, timing and output are unchanged. Only root executes actual profiling.

The caller hashes frozen sources, serialized models and training inputs before and after, preserves existing logs, refuses an existing profile.json, creates a one-shot STARTED receipt, and records success or failure with no automatic retry. Public regression tests serialize a never-fitted synthetic scalar head with __main__.Model, reproduce the exact load failure, then run the real frozen profiler against 176 authored synthetic archive-shaped rows with the alias. Only root-completion metadata is mocked in that public integration test; joblib loading, feature loading, sampling and prediction timing use the actual frozen code. No actual models or datasets are opened by those tests.

Root CLI accepts `--compat-protocol`, `--compat-protocol-sha256`, `--authorization-plan`, `--completion`, `--plan`, `--source-freeze`, `--methods`, `--rows`, `--output`, `--max-seconds 300`, `--execute`, and `--records` followed by the same original record paths. Put `--records` last, or terminate its path list with another named option. There is no fitting or prediction-save command.
