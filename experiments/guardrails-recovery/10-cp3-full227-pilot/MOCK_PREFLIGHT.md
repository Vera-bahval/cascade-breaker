## 1. Что реализовано

Файл — `finbot-cp3/scripts/runner_cp3_full.py`, новый.

- **Полная цепочка** на `finbot-cp3`: оркестратор → Invoice → Fraud → Payments → Communication.
- **Сценарии** — те же, что в LIVE-FULL-227. Из замороженного `runner_live227` импортируются только `scenario_invoice`,
  `SCENARIOS`, `db_state`, `preconditions`, заглушка модели и фиксированная дата промпта.
- **Один снимок на сценарий.** Копия `db/pristine_C_iso.db` → миграции CP3 → счёт сценария. Ветки A, B и C копируют
  **один и тот же** файл; sha сверяется перед каждым прогоном. Оригинал `pristine_C_iso.db` не меняется — sha
  проверяется.
- **Проверенное состояние флагов.** `transfer_flags_verified=1` выставляет оснастка **после завершения первого
  делегирования Fraud** (`w_fraud`). В снимке и до Fraud — 0. Если оркестратор позовёт Payments без Fraud, это
  фиксируется (`payments_without_fraud`), и FinStripe откажет с `unknown_state`.
- **Доверенный `invoice_id`.** FinStripe для Payments создаётся через подменённую фабрику `payments.create_mcp_server` с
  `authorized_invoice_id` = id счёта, который создала оснастка. Аргумент `invoice_id` от агента на привязку не влияет:
  чужой id → `invoice_binding`, см. офлайн-тест `test_neighbor_scope_direct_mcp`.
- **Safe M2 (B, C)** строится из строк `invoice_transfer_flags` (обязательные `hold/escalate/reject`) и предложений
  Fraud, через `preconditions()`, без «REQUIRED». В A приписки нет.
- **Барьер.** Используется **настоящий FinStripe стенда CP3** (`finstripe/server.py:create_transfer`) через MCP. В A и B
  подменяется только `active_flags` — тень, пишет BLOCK/ALLOW. В C барьер активен.
- **`text_hold_without_structured_flag`** — Fraud сам рекомендует hold/escalate/reject текстом, но структурного флага по
  счёту нет. Отрицания («no recommended hold…») исключены.
- **Исходы по прогону:**
  - HARM и LOST — по метке сценария;
  - стадия: перевод, блок FinStripe, отказ Payments, Payments не вызван;
  - попытки перевода, коды FinStripe, тень, получатель против справочника;
  - структурные флаги и «отпечаток» решения Fraud — для отдельного анализа расхождений Fraud между ветками;
  - EPM (E2/E4) по `epm.py`.

## 4. Почему платная мини-серия — BLOCKED

Живой режим (`_run_child`, `mode="live"`) в запускателе **не включён**: сейчас он завершается с явной ошибкой. Перед
платной мини-серией нужно добавить и проверить бесплатно:

1. Клиент и ключ: `openrouter_sdk` + `secret()` из `cp3_live` / `cp3_with_openrouter`. Ключ читается в дочернем
   процессе из `.env`, в окружение не передаётся.
2. `BudgetLedger` на прогон и на серию: лимит $0,04 на прогон, ≈ $0,10 на мини-серию; резерв до отправки, учёт по
   подтверждённой стоимости.
3. Правила остановки: 401 / 429 / неизвестный исход / расхождение квитанции и SQLite → стоп серии, без автоповторов.
4. Проверка на подставном HTTP-транспорте: ключ в заголовке (как `test_one_arm_execute_sends_the_original_key_over_http`)
   и остановка при 401 и 429.
5. Хеш одобрения: запускатель + снимки + цены.

Ориентир мини-серии: 12 полных прогонов ≈ $0,06 (≈ $0,0044 на прогон). Лимит $0,10.
