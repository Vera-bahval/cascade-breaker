## 3. Правило для основной серии (`runner_cp3_full.py`)

| исход прогона | расход | прогон | серия |
|---|---|---|---|
| `completed` | по факту | пригоден | идёт |
| `incomplete` / `failed` со стоимостью | по факту | технический | идёт, если побочные эффекты определены |
| `incomplete` / `failed` без стоимости | резерв **удержан** | технический | идёт, только если побочные эффекты определены и удержания ≤ $0,10 |
| нет `id`, прочие статусы, ошибка HTTP (401, 429, 5xx), неизвестный исход, лимит бюджета, расхождение цены, сбой оснастки | — | — | **немедленный STOP** |

Остальные критические STOP:
- перевод в C при активном флаге (`barrier_failure_C`);
- изменение защищённых файлов DI и Safe M2 — проверка после каждого прогона;
- неопределённые побочные эффекты.

«Побочные эффекты определены» проверяется по каждому прогону:
- у каждого вызова `create_transfer` есть результат;
- все переводы в SQLite `completed` и совпадают с квитанцией FinStripe и получателем из справочника;
- счёт `paid` тогда и только тогда, когда есть завершённый перевод.

Незавершённый или сбойный ответ модели в цепочку не передаётся. Автоповторов и автозамен нет: технические прогоны
попадают в `technical_runs_to_replace`, замена — отдельным решением.

## 10. Возобновление серии после STOP

**Что делает.** `full227-resume <хеш>` продолжает остановленную серию в том же каталоге `full227-v1`, только дописывая
новые файлы.

- **Без повторов.** Ячейки, у которых есть строка в `rows.jsonl`, не запускаются снова: ни пригодные, ни технические.
  Технические заменяются только отдельным решением.
- **Снимки** берутся прежние: sha сверяется с `snapshots.json` и `state_before.json`, файл не пересоздаётся. Снимок,
  подготовка которого прервалась, сохраняется под именем `*.incomplete-segNN` и готовится заново.
- **Порядок и ветки A/B/C** — тот же замороженный порядок из 681 прогона, минус уже сделанные.
- **Бюджет переносится.** Подтверждённые расходы прошлых сегментов и неподтверждённые резервы считаются в общий лимит
  $4. Лимит удержаний $0,10 общий на всю серию и автоматически не поднимается. Если перенесённые удержания уже больше
  $0,10, при возобновлении не стартует ни один прогон.
- **Сверка с OpenRouter.** Удержание снимается только записью в `reconciliation.json` ({id запроса: фактическое
  списание}). Эта запись входит в хеш возобновления.
- **Прерванный прогон** (умер родительский процесс) не удаляется. Его подтверждённые вызовы учитываются как расход,
  неподтверждённый запрос — как удержание. Ячейка запускается рядом, в `<ячейка>__segNN`.
- **Трассы.** Прежние файлы не меняются: до и после сверяется манифест всех файлов. Перезаписываются только сводные
  `summary.json` и `snapshots.json`, а `rows.jsonl` только дописывается. У каждого сегмента своя запись
  `segments/seg-NN.json`.

**Когда возобновление разрешено:**
- остановка по `hold_cap` или `series_budget`;
- прерывание;
- сбой провайдера: 401, 429, неизвестный исход, ответ без `id`, неизвестная стоимость.

**Когда запрещено:**
- серия завершена;
- перевод в C при флаге;
- неопределённые побочные эффекты;
- изменены защищённые файлы;
- сбой оснастки;
- расход выше резерва, несоответствие модели или маршрута.

Такие случаи сначала разбираются.

**Одобрение.** Хеш возобновления (`approval-hash full227` с флагом resume) включает весь основной хеш и точное
состояние остановленной серии:
- манифест всех файлов;
- причину остановки;
- номер сегмента;
- перенесённые расходы и удержания;
- прерванные прогоны;
- `reconciliation.json`.

Любое изменение в каталоге серии даёт новый хеш. Каждое возобновление требует отдельного «ок».
