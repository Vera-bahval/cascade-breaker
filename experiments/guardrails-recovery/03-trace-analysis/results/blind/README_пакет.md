**Что скрыто:**

- серия и ID сценария (в ID зашит профиль — это раскрыло бы исход по оракулу);
- пространства имён и нестандартные номера счетов;

**Что выдаёт руку и не скрывается — это и есть размечаемый материал:**
- в A2 действия Payments показывают исход;
- у nano нет текста рассуждений (в C вместо них — действия оркестратора);
- стиль текста nano и Flash различается;
- до PR #8 во входе Payments есть блок `[context from previous steps]`.

Остаточные совпадения «prior workflow» (5) — слова самих агентов в отчётах, не заголовок.

**Риск узнавания одинаковых трасс между парными листами** (`link_check.py`: для каждой строки A1 ищем строку A2 с
максимальным совпадением «отпечатков»).

| признак | A1 → A2, найдено верно и однозначно | B1 → B2 |
|---|---|---|
| до псевдонимов: номера счёта и поставщика | 73 / 115 | 53 / 71 |
| после псевдонимов: только даты | 15 / 115 | 6 / 71 |
| после псевдонимов: только суммы | 41 / 115 | 16 / 71 |
| после псевдонимов: все числа вместе | **72 / 115** | 17 / 71 |

- Псевдонимы идентификаторов (своя нумерация в каждой строке) убрали связь по номерам. Но **суммы и даты связывают
  до 72 из 115 пар A1/A2**. Убрать их нельзя: на них опирается разметка (причина флага, проверка Payments).
- **Поэтому защита процедурная:**
  1. A1, B1 и C размечаются и сдаются первыми; их файлы фиксируются хешем до выдачи A2 и B2;
  2. метки A1/B1 после выдачи A2/B2 не меняются;
  3. лучше — разные разметчики для A1/B1 и для A2/B2.
- Остаточный риск: в A2 разметчик может узнать прогон из A1. Исход A2 тогда не влияет на A1 (он уже сдан). A1-часть
  во входе Payments и так видна в A2.
- **B2 показывает цитату условия**, найденную детектором. Значит, строка — кандидат. Поэтому B1 (где есть
  «отвлекающие») размечается раньше.
