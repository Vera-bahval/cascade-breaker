# Инвентаризация сохранённых методов для независимой разметки

Основа: `representative-actual-hook-metrics.json`, 542 уникальных фактических P4 before-tool состояния из REPRESENTATIVE. Новые прогоны, обучение и изменение прежних данных не выполнялись. Файлы, SHA-256, число строк, уникальных случаев, дубликаты и распределения сохранены в `inventory.json`.

**Соединение.** Для текущих файлов использовать `case_id + checkpoint=P4 + event_seq`, затем точные `method`, `placement`, `head` и проверку уникальности. Независимую разметку привязать по замороженному `case_id`; не использовать для P4 поздний итог полной трассы или proposal-bound наблюдение. В старых strict/v4 файлах совпадает суффикс prefix ID, но старый event_seq на 2 больше во всех 542 строках: отчёт аудита документирует исправление старой нумерации. Это подтверждает согласованную нумерацию, но само по себе не доказывает эквивалентность входной проекции или обязательств метода. Другие режимы strict/session/technical и синтетические результаты не подменяют исторический общий вход.

**Интерпретация.** UNKNOWN остаётся в знаменателе; отдельно показывать отсутствие входа, UNKNOWN метода и ошибки. Исторические исходы и старые метки не заменяют новую независимую разметку. P4 решения являются офлайн-проверкой сохранённого состояния, а не доказательством реального предотвращения вреда. Дополнительные контракты v3/v4.2 и цели ML отличаются от native; единый счёт без раскрытия различий вводит в заблуждение.
