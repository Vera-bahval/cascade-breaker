# Повторная оценка сохранённых ответов на реальных сессиях

Задача этапа: восстановить основания для сравнения правил, ML и DeepSeek на 542 сохранённых состояниях непосредственно перед переводом. Раньше для части этих состояний отсутствовала исходная целевая метка. Теперь проверены исходные категории сценариев и независимо оценено предлагаемое платёжное действие.

Новые исполнения FinBot, обучение, предсказания правил/ML и запросы DeepSeek не выполнялись. Использованы прежние ответы. Новая работа состоит из извлечения исходных свидетельств, разметки Terra и пересчёта метрик.

## Что сравнивается

[Основные и полные таблицы](TABLES.md) относятся к одним и тем же 542 фактическим состояниям перед вызовом инструмента перевода, из 58 базовых групп представительной части ранее выбранного архива. Поздний исход исполнения не показывался оценщикам. Повторы одной задачи учитываются как связанные наблюдения при расчёте интервалов.

В таблицах разделены два вопроса:

- Как метод ведёт себя на исходно обычных задачах, инъекциях, сценариях фрода и проверках политики. Категория берётся из сохранённого авторского поля `truth`, а не из ответа защитника.
- Правильно ли метод разрешает или запрещает конкретное действие по требованиям FinBot и сведениям до перевода. Это новая модельная разметка с отдельной категорией недостаточных свидетельств.

Авторская категория не определяет автоматически правильный платёжный вердикт. Инъекция может не повлиять на действие. В обычной задаче исполнитель может нарушить платёжные условия. Поэтому число блокировок сценариев с инъекцией нельзя без дополнительной проверки назвать числом предотвращённых вредных платежей.

## Как получена разметка

Каждый вход независимо оценили два агента Terra в свежих контекстах. Им были доступны политика и события до действия; исходные цели сценариев, прежние оценки и предсказания методов не передавались. Затем отдельные оценщики разобрали все расхождения в итоговых решениях и статусах требований, а также по одному детерминированно выбранному случаю из каждой базовой группы. Из 542 пар две исходные оценки второго оценщика содержали неразрешённую интерпретацию, впоследствии разобранную отдельно; среди остальных 540 пар совпали 527 итоговых меток. Всего на третью проверку отобраны 272 состояния; 270 совпавших оценок унаследованы с указанием происхождения. Это модельная исследовательская разметка, не человеческий эталон.

Один первоначальный пакет первого оценщика исключён из-за просмотра сводки других агентов; его 15 записей заменены полным разбором в новом контексте. Один незавершённый пакет также заменён. Исключённые версии сохранены, но сборщик их не использует. Общая файловая система позволяла читать чужие данные: разделение обеспечивалось инструкциями и журналами чтения, технической изоляции не было.

Дополнительные источники извлекал отдельный агент. В ходе поиска он встречал смешанные файлы с исходами и старой разметкой; это отмечено в журнале. Оценщикам переданы только ограниченные проекции до рассматриваемого действия. Их содержимое и связь с архивами зафиксированы хешами. Точные дополнительные сведения о доступных инструментах найдены для 48 прежних сессий и 39 сессий из архивных пакетов. Отсутствие списка инструментов не приравнивается к отсутствию самого инструмента.

До фиксации итоговой разметки исправлена неоднозначность условия налоговой проверки: уже выполненная применимая проверка может удовлетворять требованию без отдельного доказательства доступности инструмента. [Уточнение](N14_CLARIFICATION.md) и [проверка соответствующих случаев](N14_REVIEW.md) сохранены отдельно; исходный протокол и прежние оценки не переписаны. Остальные неизвестные сведения не восстановлены предположениями.

Исходные авторские категории подтверждены для 494 состояний: 160 обычных задач, 216 инъекций, 110 проверок политики и 8 сценариев фрода. Для 48 категория не восстановлена. Отдельная попытка определить намерение только по содержанию запросов дала значительно больше неизвестных; её результаты сохранены как дополнительная ось, а не подмена авторских категорий.

## Что означают метрики

Корректное определённое решение — ALLOW при подтверждённой допустимости либо BLOCK при установленном нарушении. Основной знаменатель — все 542 состояния, включая неопределённые. UNKNOWN не считается решённым случаем. Если оценщики не смогли применить требование однозначно, это отдельно записывается как неразрешённая разметка; установленный недостаток свидетельств имеет метку INSUFFICIENT.

Недоступность старого конструктора входа показана отдельно от UNKNOWN исходного метода. Сохранённый технический ответ остаётся в исходном файле. Совпадение идентификаторов старого теста без совпадения входных сведений недостаточно для включения его результата в общий рейтинг.

Пересчёт описывает ответы в сохранённых состояниях. Он не измеряет предотвращённый ущерб, поведение исполнителя после запрета или адаптацию LLM к новым правилам. Дополнительные источники, полученные для разметки, не подмешаны в прежние входы методов; они служат проверке правильности сохранённых ответов.

## Артефакты и воспроизведение

- `annotation-freeze.json`, `custodian_manifest.json`, `action_inputs/`: исходная выборка и её фиксация.
- `PROTOCOL.md`, `READING_GUIDANCE.md`: требования к оценке и чтению свидетельств.
- `labels/`, `adjudication/`: две оценки, решения по расхождениям, журналы чтения и сохранённые прежние версии.
- `assemble.py`, `consensus-freeze.json`: проверка полноты и фиксация итоговой разметки до подсчёта результатов.
- `score.py`, `results/scores.json`: сопоставление с прежними ответами; проверки хешей, идентификаторов, точки P4 и номера события.
- `render.py`, `TABLES.md`: таблицы из сохранённого пересчёта.
- `describe.py`, `results/annotation-summary.json`, `EXAMPLES.md`: причины неопределённости, парное различие методов и примеры.
- `ANNOTATION_AUDIT.md`, `SCORING_AUDIT.md`: независимые проверки с явно указанным объёмом.

Команды пересчёта приведены в [SCORING_USAGE.md](SCORING_USAGE.md). Сборщик отказывается перезаписывать итоговую разметку, а скоринг — существующий файл результатов. Для повторной проверки следует использовать новый путь результата. Модели и их ответы не запускаются заново.

Исходные дополнения и сведения о сценариях хранятся в четырёх `source-bundles/*.tar.gz`, чтобы тысячи небольших свидетельств не перегружали просмотр PR. `source-bundles/manifest.json` содержит хеш каждого архива и каждого файла. Для чтения первичных свидетельств восстановите их рядом с остальными артефактами:

```sh
python3 experiments/local_guards_archive_annotation/unpack_sources.py
```

Распаковка проверяет все хеши и отказывается заменять отличающийся файл. Для пересчёта готовых таблиц распаковка не требуется: входы, консенсус и скрипты хранятся отдельно.
