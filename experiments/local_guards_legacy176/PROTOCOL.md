# Legacy176: сохранение бейзлайна и время всей задачи

Основание: утверждённый пользователем план. База7fb7902a; старая опубликованная серияec93a1be. Фиксированы176 эпизодов,83 положительных и93 безопасных. Это открытая проверка регрессии, без новых модельных вызовов, обучения и порогов.

Основное сравнение: исходные v1/v2, v3/v4.3, native_core/native, сохранённые SecJev и константы ALLOW/BLOCK. v4/v4.2 и платёжный профиль v4.3 сохраняются диагностически. Наблюдения полные исторические; отдельно partial без начальных объектов/ledger. Старые ответы SecJev включаются только при совпадении hash canonical input и point/cut; их CV или фиксированный порог явно обозначаются, результаты не выбираются по качеству.

Подготовка отделена от оценки. Custody извлекает только initial, предшествующие события и текущий pre-action snapshot; final DB/guard verdicts/label исключаются из входа. Старый неизменённый builder проверяется на равенство state и воспроизводит78/83,0/93 и83/83,0/93. Новый builder вызывает существующий evidence/adapters и передаёт независимый снимок БД как server_snapshot, без выдуманного source_call_id. Факт и его пригодность frozen методу различаются; непринимаемый source сохраняется и объясняется, а не переименовывается в удобный.

Новые предсказания не запускаются до независимого допуска commit+input manifest. После него: сохранение предсказаний до чтения scoring labels, качество, парные переходы и bootstrap по старым группам(seed17,2000 повторов). UNKNOWN не TP; BLOCK FPR и STOP safe отдельно. Новые бизнес-условия не меняют исходную разметку. Полные регрессии v2 публикуются со свидетельствами.

Время: old wall_s сохраняется. Источником исторической схемы пауз служит сохранённая копия, совпадение которой с raw проверяется явно; её полная идентичность отсутствующему631100dc не утверждается. Подтверждённые интервалы старых verifier wait удаляются объединением, вложенные delegate durations повторно не вычитаются. STOP в P4 использует время до действия без текущего verifier wait; ALLOW — очищенное полное время. После STOP поздние события исключаются. Исходное завершение/ошибка сохраняются отдельно; ALLOW не означает успешное завершение.

Локальный benchmark: все176 входов,30 повторов,seed17, перемешанный порядок; сбор доказательств/адаптация, решение и экспериментальная диагностика отдельно. Для полной цепочки складываются компоненты каждого эпизода до вычисления mean/median/p95. Публикуются все terminal episodes, completion и STOP отдельно, paired overhead на том же completion-подмножестве. Отдельно хранится наблюдаемое wall_s со старым shadow overhead. Время сохранённого SecJev — исходное вычисление необходимых вопросов/точек плюс head только где известно, не чтение кеша. Пропуски времени не заменяются нулями.

Основной расчёт времени локальных методов относится к P4-размещению. SecJev J_seq оплачивает все необходимые более ранние измерения, J_cur — только текущие четыре atomic questions. Перенос фиксированных архивных ответов не измеряет адаптацию живой LLM.

Два независимых gate: входы до новых вердиктов, затем весь результат/отчёт. Публикация в PR7 без merge. Изменение frozen методов или новых требований в эту оценку не входит.

Captured callable schemas предшествующих запросов сохраняются. Единственный согласованный server-declared default валюты применяется только к аргументу перевода при его пропуске; валюту счёта он не устанавливает. Эти schema сведения сверх старого SecJev renderer явно отмечаются; старые canonical входы и scores остаются неизменными.
