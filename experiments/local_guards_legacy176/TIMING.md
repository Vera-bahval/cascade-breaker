# Время всей задачи

Все значения в секундах, единица наблюдения: эпизод. Локальное время одного эпизода усредняется по 30 измерениям, затем считаются статистики 176 эпизодов. ALLOW сохраняет весь последующий архивный ход; BLOCK/UNKNOWN обрывает его перед первым переводом. Последующие инструменты и проверки после STOP не учитываются. «Завершение» означает успешное окончание исходного исполнения, не доказанную безопасность оплаты.

Исходный wall_s включает старые теневые проверки: среднее 48,052 с, медиана 47,675 с, p95 55,030 с (n=176). После удаления объединения 2343 интервалов ожидания: 31,515 / 31,226 / 38,280 с. Суммарно удалено 2910,5895 с. Вложенные вызовы делегирования не складываются; время кеша не подменяет вычисление модели.

## Источники и точность

[Независимый аудит таймеров](TIMING_SOURCE_REVIEW.md) устанавливает порядок записи контекста после ожидания. Архив указывает ревизию 631100dc; полного исходного объекта локально нет. Проверена сохранённая реализация runtime 08b7b900 с тем же порядком таймеров и согласованность всех trace-интервалов. Номинальный расчёт вычитает pause_ms; дополнительная консервативная граница вычитает весь промежуток между соседними событиями. Очищенная база по этой границе: среднее 31,462, медиана 31,180 с. Разница с номинальной около 53 мс на эпизод, максимальная погрешность округления около 5,7 мс. Все нижние границы сохранены в full-time.json, это не претензия на новый live-замер.

Локальный benchmark: изолированная SQLite хранит архивный префикс; чтение и JSON-разбор, построение доказательств, адаптация и решение измерены отдельно. Это измерение выбранной replay-интеграции, а не производственной интеграции FinBot. Вывод артефактов и диагностическое хеширование исключены из рабочего времени; payload и вердикты совпали во всех 58 080 измерениях. Для v1/v2 учитывается только их исходный конструктор; константы не оплачивают ненужный сбор. Средняя добавка на завершившихся задачах: v1 1,64 мс, v2 1,83 мс, платёжные условия с Fraud 12,10 мс.

SecJev 0.8B: одна точка содержит четыре атомарных ответа; четыре точки содержат 16. J_cur использует текущую точку, J_seq вычисляет признаки четырёх точек и принимает итоговое решение на P4; это не каскад с ранней остановкой. Для кешированных одинаковых входов берётся исходное reference-время. Последние 9B/27B scores имеют те же canonical payload hashes, но различный runtime. Накладные расходы отсутствуют явно, а не заменяются стоимостью чтения кеша.
