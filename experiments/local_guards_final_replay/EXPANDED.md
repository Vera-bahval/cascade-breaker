# Восстановление исходного состояния по архиву

Правила v1/v2 сравнивают перевод с исходными реквизитами и учитывают предыдущие переводы. Для проверки этих правил нужны исходная запись счёта, карточка поставщика и полный список транзакций на старте. В режиме expanded эти данные добавляются, если их сохранили при запуске или их можно восстановить по проверенному коду запуска и привязанной к нему базе. Входные данные размеченных P4 берутся из [манифеста выборки](../local_guards_archive_annotation/custodian_manifest.json) и [канонического сборщика](../local_guards_archive_comparison/provenance/collector-report.md).

## Что сохранилось для 542 P4

| Источник | P4 | Исходное состояние |
| --- | ---: | --- |
| Старые журналы `mini_old` | 48 | Сохранённый `db_initial` со списком транзакций. Используется без изменений |
| Основные прогоны DeepSeek | 29 | Восстановлено по манифесту, заданию, воркеру и базе |
| Основные прогоны Luna | 9 | Восстановлено тем же способом |
| Пилот DeepSeek, `fpr/TH601-r1` | 1 | Восстановлено по сохранённому `pilot/execution.json` и тому же воркеру |
| Архивы mini | 411 | Полный список исходных транзакций недоступен |
| Архивы nano | 44 | Полный список исходных транзакций недоступен |

494 строки без исходного состояния в канонических данных относятся к 24 tar-файлам. В 13 архивах mini/nano есть параметры сценария, хуки и итоговые выгрузки. В них не найдено стартовой базы или манифеста, связывающего конкретный эпизод с байтами стартовой базы и версией запуска. Код генерации профилей и чтения по ходу эпизода дают отдельные факты, но не доказывают полноту начальной коллекции. Для 455 строк это ограничение остаётся. Находки в основном и пилотном архивах DeepSeek/Luna покрывают 39 из 494 строк, то есть 7,9%. Инвентарь источников доступен в [манифесте сборщика](../local_guards_archive_comparison/data/collector-manifest.json).

## Как связаны источники

[Модуль expanded](expanded.py) сверяет SHA-256 опубликованного tar и нужных членов с [манифестом архивов](../../../../research/finbot-four-model-report/experiments/control-placement/four-model-comparison/artifacts/manifest.json). В `deepseek-source-and-acceptance.tar.gz` и `luna-source-and-acceptance.tar.gz` лежат версии `worker.py`, `experiment.py` и манифесты. Хеш параметров исполнения совпадает с `job.json.execution_fingerprint`, а хеш задания входит в идентификатор рабочего процесса в первом хуке. Для основного прогона сверяются также индекс, повтор и поля сценария из замороженной матрицы. Для пилота проверяется его отдельная запись исполнения.

Оба манифеста содержат SHA-256 исходной базы `0af3fb44d69755ad7b552756218b118ecad906e048e9412898db1a447cc7a1e7`. Этот хеш совпадает с байтами [pristine_C.sqlite.gz](../../../../deepseek-flash-control-placement/experiments/control-placement/deepseek_flash/results/paid/pristine_C.sqlite.gz) после распаковки. Запрос к базе вернул одного поставщика, пять исходных счетов и ноль строк в `payment_transactions`. Воркеры копируют эту базу при создании изолированной среды, настраивают регистрацию хуков и создают один счёт для поставщика 1. Связанные с запуском хеши скрипта, репозитория и модели FinBot подтверждают запись счёта со статусом `submitted`. Номер, сумма и описание следуют из задания и кода воркера. Идентификаторы счёта и поставщика сверяются с первым историческим хуком.

Снимки `snapshot.sqlite.gz`, `database.json` и `*.db.json` из папок эпизодов относятся к завершению исполнения. Их содержимое не используется для заполнения состояния до действия. Код не переносит назад результаты последующих вызовов. Метки и решения методов не служат источниками фактов.

## Состояние к моменту действия

Модуль оставляет исходный снимок отдельно от наблюдений к срезу. Он переносит значение из стартового состояния только по непрерывной записи до среза, если проверенные реализации предшествующих инструментов не могли изменить это значение. Неизвестный инструмент или SystemUtils закрывают этот путь. Новое наблюдение и явная потеря достоверности из канонического сборщика имеют приоритет. Для каждого из 39 P4 удалось подтвердить, что счёт и поставщик относятся к пространству запуска, а история переводов на момент предложения пуста и содержит ноль завершённых переводов. Последнее следует из чтения полной начальной коллекции и отсутствия вызова, который мог создать перевод, до среза.

Для раннего среза подтверждение настроек запуска можно получить из тех же источников, включая первый хук при пустой истории до P0. В квитанции `runner_binding` перечислены заданные историческим воркером область имён, учётная запись, тип портала, поставщик, счёт и срок жизни сессии. Она не содержит созданный заново идентификатор сессии, доказательство её действительности, подтверждение человека, сведения о налоге, валюту счёта или список вложений. Условная регистрация сессии относится к отдельному режиму воспроизведения.

Проверка охватила все 542 строки. Для каждой совпали идентификаторы, положение среза, предложенное действие, исходная последовательность событий и исторический контекст. При неверном хеше архива в метаданных эпизода исходное состояние осталось неизвестным. Непрозрачный вызов SystemUtils сохранил доказанный стартовый снимок и отменил перенос значений к срезу. Новых запусков FinBot и обращений к моделям не было.
