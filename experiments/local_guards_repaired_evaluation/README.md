# Повторное сравнение правил и ML на исправленных входах

В этом эксперименте заново выполнены локальные методы на пакете адаптеров,
прошедшем независимое ревью. Сохранённые ответы DeepSeek переиспользованы;
модели не обучались, FinBot с живым исполнителем не запускался.

## Данные и методы

Исходный коммит c42ca383. Допуск второй подготовки относится к коду адаптеров b20c6587 и манифесту
`5915413af785c1016e0047439f9b4d9c6af8f22680544491486c068767acdc51`.
Новый код находится здесь; исправлены входы. Исходные методы, веса,
определения признаков, пороги, состав выборок и метки не менялись. [Протокол](PROTOCOL.md) записан до предсказаний,
[configuration.json](configuration.json) фиксирует точные варианты и хеши.

- P4:542 состояния,58 базовых групп, только прежняя представительная выборка.
  Common использует сведения сохранённого запроса. Expanded добавляет
  подтверждённые архивные сведения до действия. Conditional добавляет явно
  объявленный технический контекст воспроизведения. Нового ответа DeepSeek
  для expanded/conditional нет.
- Ранние действия:18 676 точек из754 эпизодов, два режима сведений. Качество
  оценено по прежним128 меткам; остальные точки используются только для
  описания наблюдавшихся цепочек и первой остановки.
- Исходные v1/v2/v3/v4/v4.2, отдельный v4.3, два варианта требований записанных
  сессий и228 закреплённых ML-конфигураций. С профилями, вариантами порогов,
  диагностикой и константами получается569 строк методов P4,18 ранних
  конфигураций. Сохранены все seeds17/29/43 и обе версии переобученных ML.

Получено1 597 530 локальных записей предсказаний в587 файлах. Число записей
не является размером независимой выборки. Receipt каждого worker фиксирует
его выходы. prediction-freeze.json составлен до чтения меток генератором
оценки. Подготовка и предсказания не читают метки и итоговые БД; сеть из runner
блокируется. Незавершённая техническая попытка записи хешей и первый пересчёт с потерей
legacy-событий исключены; все публикуемые предсказания получены заново
после исправления и нового независимого допуска входов.

## Время и расход

Benchmark вызывает исходный одиночный путь с признаками и проверкой разрешения
по готовому наблюдению. По30 префиксов выбраны до измерения с seed17; для v1/v2
пригодных среди них меньше. Файловое чтение, проверка хешей и диагностика не
входят во время решения. Загрузка и первый вызов в общем процессе сохранены
отдельно, с явным указанием, что это не изолированный холодный старт.
Пиковая память сохранена в benchmark/receipt.json; это общий процесс всех
локальных методов, не память отдельной модели.

Все38 120 одиночных решений совпали с пакетными по входу и вердикту. Для основной
части ML использованы существующие FeatureBatch и batch API; среднее время
batch не выдаётся за время одного запроса. Основной и ранний пересчёт не
измеряют получение текущего состояния из работающего FinBot.

Новых запросов моделей:0. Повторное использование542 старых ответов не
расходует квоту Eliza. Их прежние фактические списания, задержки и токены
сохранены в results/saved-deepseek.jsonl.gz; они не являются стоимостью этого
повторного эксперимента. Локальные вычисления в доллары не переводились.

## Воспроизведение

Python и зависимости закреплены в ../local_guards_adapter_repair/environment.json.
Здесь использовано существующее окружение с numpy,scikit-learn,catboost.
Из корня рабочего дерева:

```sh
python -m unittest experiments.local_guards_adapter_repair.test_evidence experiments.local_guards_adapter_repair.test_prepare experiments.local_guards_repaired_evaluation.test_evaluation -q
python -m experiments.local_guards_repaired_evaluation.audit
python -m experiments.local_guards_repaired_evaluation.manifest --check
python -m experiments.local_guards_repaired_evaluation.render
python -m experiments.local_guards_repaired_evaluation.examples
```

Для повторного расчёта оценок по опубликованным предсказаниям нужен новый каталог:

```sh
python -m experiments.local_guards_repaired_evaluation.evaluate --output /tmp/finbot-reproduced-scores
```

Для повторного вывода моделей сначала проверяется допуск и фиксируется
configuration.json. Каждый worker должен писать в новый каталог:

```sh
python -m experiments.local_guards_repaired_evaluation.run --freeze
python -m experiments.local_guards_repaired_evaluation.run --group rules --output /tmp/finbot-reproduced-predictions/rules
python -m experiments.local_guards_repaired_evaluation.run --group v3_ml --output /tmp/finbot-reproduced-predictions/v3_ml
python -m experiments.local_guards_repaired_evaluation.run --group archive_ml --output /tmp/finbot-reproduced-predictions/archive_ml
python -m experiments.local_guards_repaired_evaluation.run --group frozen --output /tmp/finbot-reproduced-predictions/frozen
python -m experiments.local_guards_repaired_evaluation.run --group frozen_revision2 --output /tmp/finbot-reproduced-predictions/frozen_revision2
python -m experiments.local_guards_repaired_evaluation.benchmark --output /tmp/finbot-reproduced-latency
```

Генератор оценки по умолчанию проверяет публикуемые predictions/. Для новой
полной реплики передают `--predictions /tmp/finbot-reproduced-predictions`,
сохраняя receipt и configuration.json. Вердикты и причины должны совпасть, измеренные времена
могут отличаться. Метки по хешам проверяются отдельно от предсказаний.

## Границы

Исходные v4/v4.2 сохраняют собственный строгий контракт доказательств;
их UNKNOWN не означает потери восстановленного факта адаптером. v4.3 отдельно
меняет приём доказательств. Метки относятся к требованиям записанных сессий,
а новые ограничения B описываются отдельно от обнаружения атаки. Поздние
действия после первого STOP не засчитываются как достигнутые. Итоговый вред
из финальной БД не подмешивается в признаки; новое предотвращение вреда
и качество адаптирующегося LLM-исполнителя этим replay не установлены.

Это повторный анализ ранее открытых архивов. Предыдущие320/800 состояний
остаются тестами реализации и не входят в эти542 архивных состояния.
