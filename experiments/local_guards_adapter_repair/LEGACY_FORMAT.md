# Дополнение к подготовке: старый формат журнала

При проверке сравнения после первого допуска обнаружены два дефекта
интерпретации исходных записей. Независимый исследователь подтвердил их по
raw source, не читая разметку и результаты методов. Первый повторный расчёт
на таких входах исключён из итогового эксперимента.

## Источник дефекта

Старый collector превращает запись завершённого LLM-обмена в before_model и
after_model, а предложенные вызовы отмечает recorded_model_proposal. Для
инструмента, у которого не записывался отдельный guard callback, выполненная
операция представлена следующей tool-записью. В compact_event не сохранены
исходные occurrence IDs и batch metadata. Поэтому требование пары callback
с точным ID отбрасывало реальные выполненные reads. Их незакрытые proposal
кадры затем мешали сопоставить возврат родительского делегирования.

Ранний экспорт использует другой вариант: завершённый legacy LLM-обмен
представлен одной before_model с source_event_kind=llm. Отсутствие after_model
здесь является свойством формата. Автомат native callback ошибочно объявлял
повторную такую запись пропуском истории и отменял актуальность поздних фактов.

Проверяемый источник: shadow-main#L90, cle-clean_09-beda74,
gzip SHA256 `0d16d93500789d716f0b07a2beab64e78af6deea03c072d66133b3480389c504`.
Prefix `1536c67c5cf20c447ef791869b1f`: reads25/26 и29/30, собственный возврат
delegate_to_invoice13/52, поздний get_invoice_for_payment158. Их имена,
аргументы и результаты сверены с raw tool records. Старый source commit
631100dc локально не подтверждён; modern runtime не выдаётся за его код.

## Общее исправление

- Actual callback frames и recorded proposals имеют отдельные структуры.
  Предложение без результата не создаёт факта и не удерживает стек исполнения.
- Выполненная legacy tool-запись сохраняется как executed-result occurrence.
  Источник вызова берётся из фактического результата. При отсутствии записанного
  ID используется явно производный ID координаты результата; исторический
  beforehook или authentication этим не создаётся.
- Связь с proposal выводится только для единственного точного соответствия
  в последнем model batch, без конфликта явно записанных идентификаторов,
  аргументов и источника. Неоднозначный результат остаётся наблюдением,
  но не получает придуманную связь с proposal или parent-derived полномочия.
- complete_task не закрывает родительское делегирование. У старого формата
  может быть его выполненный return, у современного terminal callback может
  отсутствовать. Это не изменение invoice/vendor состояния.
- Завершённые legacy llm records не открывают native model frame. Неизвестный
  native orphan и нарушенные настоящие callback пары сохраняют диагностику gap.
- Role для standalone legacy record без доказанного parent не назначается
  автоматически как orchestrator. Найденный результат и технические полномочия
  по-прежнему проверяются раздельно.

Формат принимает доверенный производитель входов по исходным хешам. Строка
source_event_kind в произвольном JSON сама по себе источником доверия не служит.

Проверены proposal без результата, конфликты call/workflow/session/namespace,
двойные одинаковые proposals, повторные выполненные reads, terminal sentinel,
native orphan, чужие объекты, ошибки инструментов и сведения после среза.
Отдельная регрессия подтверждает сохранение current invoice status и
представимого входа v1 на приведённом реальном префиксе.

Это вторая версия подготовки данных. Код правил v1/v2/v3/v4/v4.2/v4.3,
ML-преобразователи, модели, пороги и разметка не меняются. Изменение source
parser и входов требует нового точного допуска до повторного эксперимента.
Прежний допуск сохранён в approval-ac74e6b6.json и REVIEW-ac74e6b6.md.
