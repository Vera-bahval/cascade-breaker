# Источник, факт и представление метода

Подготовка не получает метки и результаты методов. inventory.json задаёт только
состав, координаты источников и их контрольные суммы. prepare.py проверяет
пакет запроса DeepSeek, границу действия и закреплённый код запуска.

| Что восстанавливается | Допустимое основание | Что передаётся дальше |
|---|---|---|
| Текущее действие | before_tool или соответствующий anchor; для P2 — парный возврат делегирования | proposal, context объектов, action_boundary для сверки |
| Начальная сумма, получатель и история платежей | подтверждённое исходное состояние | initial для v1/v2; baseline для v3; отдельные записи источника |
| Текущие сумма, статусы и реквизиты | последнее относящееся к объекту native-наблюдение до действия | current с актуальностью; типизированные факты и provenance v3/v4 |
| Версия записи | собственный version/updated_at конкретного объекта | отдельный журнал versions; исходная версия остаётся у своего доказательства |
| HOLD | успешный парный native flag_invoice_for_review с объектом и рекомендацией | отдельное сохраняемое обязательство; успешность не зависит от имени агента |
| Завершение Fraud | успешное связанное делегирование с наблюдавшимися native-чтениями либо подтверждённый flag | fraud_review_completed с исходным вызовом и временем |
| Подтверждённый перевод | completed receipt по объекту либо исходная подтверждённая транзакция | нижняя граница числа переводов; совпадение payment_reference только при точном соединении |
| Технический исполнитель | закреплённый runner, фактический callable/class, наблюдавшаяся цепочка вызовов | technical_actor; для P2 также delegated_actor; отдельное доказательство кода |
| Namespace и свойства конструктора | проверенный путь создания тестовой сессии | фактический контекст; без автоматического session_valid или прав на объекты |
| Условный технический допуск | явно созданные записи локального replay | только conditional, origin=replay; без финансовых разрешений |
| Валюта счёта, ручное одобрение, снятие HOLD | объявленный исходный источник либо независимое подтверждение соответствующего вида | при отсутствии источника остаются неизвестными; валюта вызова не заменяет валюту счёта |

Результат инструмента связывается с исходным вызовом. Начальное состояние
остаётся declared_fixture и не получает выдуманного source_call_id. Снимок БД
требует snapshot_id. Повторяющиеся вызовы связываются по конкретным вхождениям,
а не по одному имени инструмента. События после среза недопустимы.

Текст и строковые идентификаторы нормализуются совместно с сохранением равенств.
Для transfer_id и payment_reference используется одно пространство ссылок.
Исходный преобразователь запросов остаётся неизменным и отдельно используется
для проверки точного совпадения с сохранённым запросом DeepSeek.

## Различия получателей

- v1/v2 получают исходный конструктор и историю с различием «пустая» и «неполная».
- v3 получает исходные типы и происхождение; сравнение суммы и получателя
  сохраняет прежнее начальное или первое наблюдавшееся основание.
- v4/v4.2 получают все представимые факты. Их собственное требование версии
  или области сессии не стирает найденный факт в сопровождающем журнале.
- v4.3 получает тот же пакет с отдельной проверкой происхождения и актуальности,
  описанной в DELTA_V43.md. Бизнес-условия берутся из v4.2.
- Архивные правила получают прежнюю структуру с восстановленными значениями.
  Их отношение к повторной оценке Fraud сохраняется.
- ML получает payload и признаки из прежних чистых преобразователей.
  Определения, порядок признаков, модели, пороги и проверки допуска закреплены
  в methods.json. Здесь сохранены только входы и их хеши.

Для каждого поля coverage различает source_absent, stale, unsupported и
ограничение исходного метода. records сохраняет найденные значения и координаты
даже тогда, когда текущее представление их не принимает. audit.py проверяет
передачу каждого текущего типизированного факта в совместимые представления,
границу событий и неизменность состава. Случаи регрессий находятся в
test_evidence.py и test_prepare.py; это тесты преобразований, не оценка качества.
