# Jev 1.14 в экспериментах FinBot

TypeSafe Choice возвращает выбранный ключ, вероятность каждого запрошенного ключа и отдельное поле `confidence`. Варианты определены в запросе; ответ разбирается по ключам и по зафиксированному соответствию ключей меткам. Один и тот же ключ `A` обозначает разные действия в контрбалансированных запросах. Вероятности должны суммироваться до единицы. `confidence` для трёх вариантов равна `(3 × p_max − 1) / 2` до округления. Из двух чисел нельзя получить две независимые оценки. [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice) · [Формула confidence](https://docs.typesafe.ai/confidence#choice)

`DEFER`, `REVIEW`, `UNKNOWN` и `unclear` могут быть полноценными вариантами конкретного вопроса. У Choice нет отдельного автоматического воздержания. Решение о дополнительной проверке принимает вызывающий код. Полный вектор относится только к предложенным вариантам. Если ни один не соответствует входу, оставшийся вариант всё равно может получить высокую вероятность. Договор Choice не описывает порядок разрешения ничьей. При равных максимумах новый клиент сохраняет выбранный сервером ключ. Чуть отклонившуюся из-за округления сумму он принимает с допуском 0.001 и сохраняет числа как пришли. Усечённый вектор, неизвестный ключ, значения вне [0, 1] и явно расходящиеся победитель с максимумом отклоняются. [TypeSafe Companion Noul](https://docs.typesafe.ai/patterns/companion-noul)

Сохранённые запросы преимущественно использовали `jev-latest`; оплаченные ответы здесь идентифицированы как `jev-1.14.0`. Чтение реестра из аккаунта вернуло 200 и два псевдонима `jev-latest` и `jev-preview`. Публичная документация связывает `jev-latest` с `jev-1.14.0` и указывает $0.042 за миллион входных токенов. Для нового клиента запрос и ответ привязаны к явной версии. Проверка статуса и реестра была бесплатной. Все расчёты ниже сделаны по уже сохранённым данным. [Модели TypeSafe](https://docs.typesafe.ai/models) · [Состояние API](https://status.typesafe.ai/)

## Что удалось сверить

- 192 сохранённых типизированных ответа из `jev/responses.jsonl.gz` совпали с отдельными квитанциями по модели, использованным токенам, выбору и каждому элементу вектора. Максимальное расхождение `confidence` с формулой составило 0.005 вследствие округления. В двух документах из живой интеграции оригинальные поля сохранились. Для снятого HOLD Jev вернул `p(no_active_hold)=0.96` и `confidence=0.94`. Для действующего HOLD оба числа равны 1.00.
- Архив пилота `probe_models.py` сохраняет полный типизированный ответ. `live_jev.py` сохраняет выбранные поля ответа, включая тип, вектор и confidence. `study/enforce.py` проверяет вектор, но журналирует только выбранное действие и usage. Эти маршруты переводят ключ в действие напрямую.
- `native/overnight/provider.py` и `native/mechanism_study/panel.py` проверяют присутствие альтернатив, затем хранят ключ, расшифрованное действие и хеш ответа. В 109 обнаруженных квитанциях из семи каталогов этих маршрутов вектор отсутствует. Хеш позволяет сверить найденный впоследствии ответ, но не восстановить его. `checkpoint/panel_live.py` и его вызывающие панели confirmation, register, semantic и scope сохраняют `probabilities`, но опускают исходный тип и `confidence`. Ретроспективные метрики используют только сохранившиеся векторы.
- Нативный маршрут вызывает Jev там, где имеет право на модельную развилку, и интерпретирует возвращённый ключ через зафиксированную карту. Отдельный обязательный veto управляется правилами. Вероятность и `confidence` не являются порогами этого маршрута. Локальные правила, технический сбой или признак невозможности выбрать маршрут не получают искусственного вектора.
- Исполняемые файлы исторических маршрутов зафиксированы в нескольких SHA-256 манифестах. `jev_choice.py` содержит новую версию клиента для нового прогона. Она хранит исходный типизированный ответ, его хеш и сумму по usage. Некорректное оплаченное наблюдение сохраняется с признаком ошибки и не подставляется как результат. Старый формат читается по сохранённому вектору, если он есть.

## Описательные метрики

Brier — средняя по строкам сумма трёх квадратов отклонения от one-hot эталона, без деления на число классов. Log loss — среднее `−ln(p_эталона)` с натуральным логарифмом. Обе оценки используют только строки с единственной допустимой меткой. Для нулевой вероятности эталона файл явно показывает бесконечность и отдельно — чувствительность к ограничению снизу на 10⁻⁶. Для нескольких допустимых меток считаем совместимость выбранного действия. В интервалах калибровки сравниваем среднюю вероятность выбранного действия и наблюдаемую совместимость. Строки и число различных исходных семейств/структур показываются отдельно. Альтернативные формы одного документа или два варианта одной семьи остаются зависимыми.

| Срез | Совместимые / строки | Различные группы | Brier | Log loss |
|---|---:|---:|---:|---:|
| Пилот, прямой вопрос без резюме | 9/12 | 6 | .3863 | .6205 |
| Пилот, вопрос о свидетельстве без резюме | 12/12 | 6 | .0295 | .0889 |
| Ранняя документная серия, confirmation | 12/12 | 12 | .0587 | .1406 |
| Нативная проверка текста Fraud | 44/44 | 44 архивные строки | .0063 | .0340 |
| Нативная оценка области применимости | 11/12 | 12 | .2351 | .4387 |
| Нативная confirmation, развилка Fraud | 5/6 | 5 | .2392 | .3630 |
| Register DC, видна связанная платёжная запись | 21/25 | 23 структуры | .1899 | .3393 |
| Register DC, без записи | 7/24 | 22 структуры | .8180 | 1.0719 |
| Register CT, видна связанная платёжная запись | 24/30 | 30 структур | .2278 | .3856 |
| Register CT, без записи | 5/24 | 24 структуры | .8329 | 1.0682 |

Для нативной оценки области применимости Brier и log loss рассчитаны на 8 строках с единственным эталоном, для нативной развилки — на 4. В Register после удаления платёжной записи эталон всех 24 строк каждого среза — `DEFER`, как в исходном протоколе. После сопоставления ключей с зафиксированной картой все ячейки матриц ошибок в точности совпали с опубликованными. В этой абляции нет нулевой `p(DEFER)`.

Две высокоуверенные ошибки в пилоте относятся к одному семейству и одному документу S03. При действующем HOLD модель выбрала REVIEW с вероятностями .94 и .95 в двух вариантах прямого вопроса, отведя правильному BLOCK по .05. В нативной задаче области применимости модель выбрала `difference` с .95 и дала .04 единственному допустимому ответу `unclear`. Это текстовая ошибка, исход перевода по ней не измерен. В нативной развилке TH502@A ошибочный CLOSE_ALLOW получил .55 против .44 у DEFER. Близкий вариант TH502@B входит в то же семейство и был отнесён к DEFER с .98. Нативная проверка текста Fraud решала более узкий вопрос и сама по себе не даёт оценки вероятности безопасной оплаты.

Изолированные строки с вероятностью выше .9 и малоразмерные срезы показывают характер ошибок. Калибровка для будущей популяции счетов, универсальный порог и независимость исходов этими наблюдениями не установлены.
