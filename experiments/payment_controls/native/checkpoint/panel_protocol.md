# Парные запросы на одном наблюдаемом входе

Новые случаи берутся из первых достигнутых P1 общих штатных запусков шести заранее выбранных обычных задач. Проверяются только строки P1:0. Используем обезличенный снимок префикса без последующих событий, оценок и ответов моделей. Случаи без P1 остаются в учёте живой серии. Одинаковый ID в нескольких условиях соответствует одному исходному наблюдению.

Запланированы три отдельных чётких вопроса из существующей панели: завершённая USD-оплата именно текущего счёта по наблюдаемой коллекции, положительная штатная проверка формата TIN и тот же вопрос после удаления свидетельства о проверке. Последний вариант применяется только при наблюдаемом положительном исходе и успешной проверке удаления повторов. Наблюдаемая пустая коллекция даёт FALSE для вопроса о содержимом коллекции. Отсутствующий результат TIN даёт UNKNOWN. Эти ответы сами по себе не завершают Fraud. В новой серии используются только данные первого реально достигнутого P1. Прямой и переформулированный вопрос о завершении Fraud и сравнение представления проверяются на уже оплаченных входах отдельной панели. Ответы сравниваются по условиям и по парным расхождениям. Технический ответ выделяется отдельно.

До новых ответов фиксируются хеши канонических пакетов и тел обоих API, набор случаев, порядок и одинаковое назначение букв для пары. Источник и достаточно однозначный эталон проверяются до разрешения вызовов. Для применения модели на рабочем маршруте нужно отдельное подтверждение, что локальные правила передали дело дальше, обязательный разбор отсутствует и результат способен обоснованно поменять маршрут. Вопросы о фактах не заменяют это подтверждение.

Берём Jev из TypeSafe System One, зафиксированную версию и тип choice, DeepSeek Flash через Eliza и одно запрошенное значение буквы без reasoning. Максимальная новая доля панели — 0,03 USD Jev и 0,06 USD Eliza. Оплата и отложенные резервы учитываются отдельно. Квоты и идентификаторы проверяются до запросов. Повтор уже подтверждённой квитанции не оплачивается.
