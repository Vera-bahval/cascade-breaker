# Сравнение правил, CatBoost и DeepSeek на 542 архивных P4

Взяли по одному предложению перевода из 542 эпизодов FinBot, всего 58 групп сценариев. Все методы сопоставлены по идентификатору префикса и границе действия. Правила и CatBoost получили структурированные представления того же предшествующего состояния. DeepSeek оценивал ранее сформированный запрос, поэтому содержимое входов и объём доступного контекста различаются. Исторические ответы DeepSeek использованы повторно. Переводы и запросы к API не запускались.

| Метод | Верный ALLOW | Верный BLOCK | Ошибочный ALLOW | Ошибочный BLOCK | UNKNOWN |
|---|---:|---:|---:|---:|---:|
| Исторические правила | 2 | 317 | 2 | 185 | 4 |
| Правила без внешнего требования N14 | 69 | 161 | 7 | 26 | 254 |
| CatBoost с сохранёнными порогами | 6 | 316 | 3 | 185 | 0 |
| Сохранённый DeepSeek | 165 | 164 | 154 | 26 | 1 |

Эталон в таблице оценивает содержание платежа. Из 542 предложений 191 допустимо по существу, 319 недопустимо и 32 остаются неопределёнными по доступным данным. Верные и ошибочные ALLOW/BLOCK посчитаны по 510 определённым меткам. UNKNOWN посчитан по всем 542. Среди 32 неопределённых предложений правила дали соответственно 0 и 7 ALLOW, CatBoost дал 0, DeepSeek дал 14. Разметку составляли с помощью моделей и последующей сверки. Независимого человеческого эталона здесь нет.

**Что изменилось после исключения N14 из архивных правил.** В обновлённом workflow применимый налог проверяет FinStripe до фиксации платежа. Удаление внешнего требования N14 в историческом входе меняет 329 ответов. Из 191 допустимого по существу предложения 67 переходят из BLOCK в ALLOW, 92 переходят из BLOCK в UNKNOWN. Среди 319 недопустимых предложений 151 переходит из BLOCK в UNKNOWN, пять переходят из BLOCK в ALLOW. У всех пяти разметка фиксирует нарушение N11, оценки банковского, исторического или Fraud-контекста. Среди 32 неопределённых предложений ещё семь переходят в ALLOW и семь в UNKNOWN. В архиве для 0 из 542 состояний сохранён полный набор полей текущей налоговой проверки, включая конфигурацию FinStripe, категорию и юрисдикцию. Поэтому этот расчёт измеряет эффект одного изменения в старых правилах. Оценка текущего P4 NativeVerifier на тех же 542 входах недоступна.

**Что CatBoost разрешает и где ошибается.** Относительно правил с вынесенным налогом CatBoost возвращает пять ошибочных ALLOW в BLOCK и превращает 151 UNKNOWN на недопустимых платежах в BLOCK. Он также блокирует 67 корректных ALLOW правил, допускает одно ранее правильно заблокированное предложение и разрешает три допустимых предложения там, где правила отложили решение. На полном историческом действии CatBoost даёт 537 верных ответов из 542 при составе эталона 536 BLOCK и 6 ALLOW. Цель по существу показывает 185 ошибочных блокировок из 191 допустимого предложения. У CatBoost было по 3–4 примера допустимого полного действия в обучающей части каждого разбиения. Использование argmax даёт те же 542 решения.

**Что меняет замена локального метода сохранённым DeepSeek.** По сравнению с правилами с вынесенным налогом DeepSeek переводит 96 UNKNOWN в ALLOW среди допустимых предложений. Среди недопустимых он переводит 144 UNKNOWN и три правильных BLOCK в ALLOW, ещё один правильный BLOCK переводит в UNKNOWN и семь UNKNOWN переводит в правильные BLOCK. Это расхождения сохранённых классификаций. Они не измеряют число реально предотвращённых или завершившихся переводов.

**Независимость.** Загрузили пять сохранённых CatBoost-моделей по зафиксированным хешам и вычислили все 542 вероятности с сохранёнными преобразователями признаков. Максимальное отклонение от запечатанных вероятностей равно нулю. В каждом разбиении группы сценариев FIT, CAL и теста попарно различны. Каждый префикс оценён ровно в одном тестовом разбиении. Девять тестовых проекций признаков совпали с проекциями в FIT своего разбиения, в CAL совпадений нет, 533 не совпали ни с FIT, ни с CAL. На этих 533 CatBoost ошибочно блокирует 177 из 183 допустимых по существу предложений. Групповое разбиение обеспечивает отложенную оценку в пределах раскрытого архива. Обобщение на новый закрытый набор этим прогоном не проверялось.

**Время и стоимость.** На исторической парной выборке из 30 состояний p50/p95 рабочих задержек составили 1,36/2,33 мс у исходных правил и 1,64/2,62 мс у CatBoost. Для локальных оценок использованы средние времена повторов на состояние, включая чтение подготовленного состояния и проекцию. Для DeepSeek p50/p95 архивных HTTP-ответов на этих 30 состояниях составили 2051/3160 мс, на всех 542 состояниях 2205/2833 мс. HTTP наблюдался при параллелизме до восьми запросов, локальные времена измерены в другом режиме. Исторические 542 вызова стоили $2,32175844. Новых платных запросов и обучений нет.

## Воспроизведение

Из корня checkout в Python-окружении с CatBoost 1.2.10, joblib 1.6.0, numpy 2.5.4 и scikit-learn 1.9.1.

```sh
python -B -m experiments.payment_controls.native.checkpoint.ml_audit > /tmp/ml_audit.json
cmp /tmp/ml_audit.json experiments/payment_controls/native/checkpoint/ml_audit.json
```

Машинный отчёт сохраняет хеши, разбивки по эталонам и переходы решений. [Скрипт](ml_audit.py) · [JSON](ml_audit.json) · [Рубрика N11 и N14](../../../local_guards_completion/PROTOCOL.md)
