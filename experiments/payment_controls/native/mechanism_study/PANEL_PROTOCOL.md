# Сравнение формулировки и видимости сведений до Fraud

План зафиксирован до новых ответов. Блок разработки включает все восемь действительных первых делегаций архивного открытого пилота. В них по старой замороженной версии правил четыре DEFER, три CLOSE_ALLOW и один CLOSE_STOP. Эти восемь наблюдений не являются новой независимой проверкой.

На одном и том же входе оба официальных провайдера получают четыре варианта запроса.

| Вариант | Чем отличается от action |
|---|---|
| action | Прежний вопрос о допустимом завершении Fraud; исходные записи представлены вложенным объектом |
| fact | Вопрос о состоянии достаточности оснований для тех же трёх исходов; определения ответов и записи те же |
| raw | Внутри state один строковый records_json. Декодирование JSON восстанавливает весь исходный объект с равенством значений |
| masked | Убраны TIN поставщика, ответ и источник проверки формата, а также прямое упоминание valid TIN в одном примечании. Это отсутствие информации, не невалидный TIN. Другие существенные основания сохранены |

Фактовая формулировка fact выше остаётся вопросом о завершении Fraud. Конкретные **отдельные** вопросы с объективным ответом TRUE/FALSE/UNKNOWN проверяют наличие ровно одного завершённого USD-перевода с совпадением invoice ID, vendor ID и principal; положительный ответ штатной проверки формата TIN на полном пакете; тот же вопрос после удаления указанного свидетельства. Эти ответы не переводятся в разрешение платить. Для операции с прежней оплатой денежный запрет может сохраняться при неопределённости полного Fraud-решения.

Порядок условий и провайдеров псевдослучаен с фиксированным seed. Перестановка значений ответов A/B/C сохраняется для всех условий и обоих провайдеров внутри одного случая; на восьми случаях каждое значение находится на каждой позиции 2–3 раза. Измеряются стоимость, технические сбои, самостоятельные завершения, решения вне допустимого множества, лишние передачи на разбор и обе стороны изменения решения на парных входах. Неединственный допустимый ответ по достигнутым префиксам сохраняет своё множество. Маскированные пакеты получили отдельную независимую разметку до новых вызовов.

На разработке выбирается один вариант Jev из action, fact и raw. Критерии лексикографические: меньше технических сбоев плюс ошибочных автоматических завершений, затем меньше лишних DEFER, затем меньше полная стоимость запросов Jev; при точном равенстве порядок action, fact, raw. Вариант masked и вопросы чтения отдельных фактов не выбираются для внедрения. На новой калибровке сравниваем победителя с action по тем же критериям. При полном совпадении условий один и тот же запрос не оплачивается повторно. Протокол фиксирует расходы именно классификатора; общая стоимость эпизода относится к живой серии. Малая калибровка охватывает пять специально заданных снимков P1 двух групп происхождения. Она не воспроизводит первые реально достигнутые шаги исполнителя и не является подтверждением безопасности.

Для обоих провайдеров используются отдельные долговременные квитанции и журналы, привязанные к телу запроса и номеру условия. Тарифы, идентификаторы моделей, расход и незакрытые резервы проверяются. Общая новая доля панели — до 0,14 USD Eliza и 0,10 USD Jev. Пустые сведения о цене и незакрытые запросы требуют сверки до следующей траты. Исторические потраченные средства и резервы остаются в агрегированном бюджете всего проекта.

Бесплатная подготовка: `finbot/.venv/bin/python -m experiments.payment_controls.native.mechanism_study.panel prepare`. После публикации таблицы покрытия и выпуска разрешающего файла — команды `run dev --release /path/to/release.json` и `run cal --release /path/to/release.json` этого же модуля. Квитанции на диске используются при возобновлении. Команда `score dev` или `score cal` повторно сводит уже оплаченные записи без вызова модели.
