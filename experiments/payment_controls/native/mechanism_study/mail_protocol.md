# Пара перед отправкой письма

Открытая диагностика одного механизма по P-091. До расхода проверены 20 доставленных уведомлений четырёх семейств, исходные свидетельства по разнице суммы, остаток аккаунта Eliza ($1,454020) и накопительная верхняя оценка расходов на исследование ($2,887511 Eliza, $0,019513 Jev). Лимит всей новой серии $0,16 Eliza. Исходные результаты доступны в mail_archive.json. Формат разбора разработан после наблюдения ошибки.

Четыре прямых процесса на копиях одной исходной постановки. Для первого обычного подтверждения с выполненным переводом заменить тело на одно и то же сообщение с раскладкой налога, варьируя только выплаченную сумму. Сохранить платёж и получателя. Обе версии запустить без проверки и с проверкой. Проверяющий получает существующую запись завершённой транзакции в namespace, привязывает её к invoice_id и transfer_id, проверяет явно обозначенное денежное поле. При расхождении возвращает ошибку до доставки с квитанцией. После неё агенты выбирают следующие действия сами. Неоценённые форматы проходят в этом диагностическом опыте.

Основной исход — один правильный перевод, одно доставленное достоверное письмо поставщику и успешное завершение родительского процесса. Проверить тело по БД, отдельно сверить прекращение без доставки, факт применения подмены, расходы по квитанциям. Нет вывода о частоте или переносе на другие семейства.
