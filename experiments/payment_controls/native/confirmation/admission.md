# Допуск к подтверждающей оценке FinBot

Проверка не нашла допущенных новых закрытых семейств для live-оценки текущего метода. По открытым данным можно выделить отдельный holdout внутри существующего каталога. В нём потолок в 16 проблемных кандидатов на начало текущего продолжения и 17 до предшествующего checkpoint из восьми задач с проблемным бизнес-состоянием по критериям ниже. Предыдущая курация договорных документов давала 82 ALLOW, 38 BLOCK и 28 REVIEW, но закрытая серия была снята до раскрытия результатов. Независимая проверка полной сцены дала 0 подходящих случаев из 160 в каждом из двух разборов.

| Цель ALLOW / проблемные | Дефицит договорного пула по классам | Открытый holdout обычных счетов | Новая закрытая live-серия |
| --- | --- | --- | --- |
| 120 / 96 | 38 ALLOW и 30 проблемных | Меньше 96 проблемных | Нет допуска |
| 100 / 80 | 18 ALLOW и 14 проблемных | Меньше 80 проблемных | Нет допуска |
| 80 / 64 | Нет дефицита для условного договорного эталона | Меньше 64 проблемных | Нет допуска |

## Открытые каталоги и прежнее использование

Исторический исследовательский след означает совпадение ID в структурированных данных анализа, разметки или replay, где есть запись работы со сценарием. Простые упоминания ID и членство в каталоге в этот счётчик не входят. След относится к исходной группе и сам по себе не доказывает, что результат использовался для настройки текущего правила. Связь со старым базовым архивом установлена по ID и маршруту. Она сама по себе не устанавливает ни использование для разработки текущего метода, ни байтовую идентичность спецификации. Отсутствие ссылки в проверенных receipts оставляет вопрос о прежнем знакомстве открытым.

| Каталог | Строки | Исходные группы | Есть связь со старым базовым архивом | Есть исследовательский след до checkpoint |
| --- | ---: | ---: | ---: | ---: |
| Unified | 1 243 | 262 | 234 | 67 |
| API-MAST | 68 | 34 | 34 | 0 |
| Встроенные CTF | 19 | 19 ID | 0 | 0 |
| Примеры раннера | 7 | 7 ID | 0 | 0 |

API-MAST и CTF учтены по метаданным. Их связь с историческими проверками не создаёт договорный эталон. Предшествующий checkpoint выбрал пять примеров раннера и три задачи Unified. Два примера раннера вне этой панели относятся к техническому отказу Payments и повторной обработке чата.

Файлы checkpoint и опись каталога созданы 18 ноября до текущего продолжения. После checkpoint число групп с ранее зафиксированной работой или выбором выросло с 67 до 69. Аудит привязки `binding_archive.json` создан в 12:11:45 уже в текущем продолжении. Он оставил 1 000 записей из 1 064 проверенных эпизодов Unified, соответствующих 185 исходным группам. Для оценки раскрытия на начало текущего продолжения аудит привязки не учитывается. Манифест хранит отдельно SHA-256 исторических материалов, предшествующего checkpoint и текущего аудита. Эти счётчики устанавливают состав проверенных артефактов. Доступ конкретного разметчика к их содержимому требует отдельного свидетельства.

## Все 28 групп Unified без базового совпадения

15 групп серии `pairs` дают 360 определений. Легитимные варианты есть у пяти ID. Остальные десять содержат только авторские policy и adversarial варианты. У всех 15 есть adversarial варианты, прочитанные только по метаданным. 13 групп серии `sweep` дают 13 policy определений. Их общая схема меняет сумму, а варианты профиля и канала повторяют исходную задачу. Ни один из 28 ID сам по себе не устанавливает отдельное договорное обязательство или дискреционную проверку. В приложенном manifest перечислены все 28 ID и число строк каждого вида.

Даже арифметика с допущением всех 28 групп как независимых даёт 148 + 28 = 176 единиц, из них максимум 82 + 5 = 87 с авторским положительным обозначением. Для 100/80 и 120/96 этого недостаточно. Этот потолок относится только к объединению прежнего сгруппированного договорного пула и 28 новых для архива ID. Такой расчёт не объединяет их в допустимый тест, поскольку источники имеют разные конечные точки и разные эталоны. Без дополнительной группировки у прежнего пула 180 заявленных lineage. Набор 100/80 упирается ровно в этот потолок и требует считать соседние синтетические шаблоны независимыми.

## Отдельный holdout внутри публичного Unified

Допустимый дизайн может использовать старые базовые записи отдельно от известных примеров разработки. Здесь посчитан верхний предел для обычных счетов Unified при одном исходном счёте на единицу, без adversarial, fraud и развёрток суммы из `pairs`/`sweep`. Отдельные счета одного профиля учитываются как разные исходные обязательства. Изменение профиля, канала или повтора того же счёта второй единицы не создаёт. Исторические исходы treatment при подсчёте не использованы. Для потенциального проблемного источника требуется хотя бы вариант авторского STOP у легитимного счёта или исходная метка policy/ambiguous, требующая независимого разбора.

Из 167 групп с базовым архивом и без найденного исследовательского следа до предшествующего checkpoint:

- 123 легитимных источника с авторским PAY во всех вариантах. Резерв положительной стороны требует независимой проверки счёта, допустимости оплаты и видимости фактов до решения.
- 13 легитимных источников с PAY и STOP при разных профилях. Это отдельные счета с одним механизмом допуска поставщика. Они дают кандидатов для проверки обязательного разбора статуса.
- Три источника с авторским policy и один ambiguous. Это четыре нерешённых кандидата, для которых авторский ярлык не заменяет независимый эталон.
- Один dirty, четыре fraud и 22 injection вне определения обычного проблемного договорного обязательства. Dirty проверяет механически недопустимую сумму.

При включении допуска поставщика предел проблемной стороны составляет 13 + 4 = 17 разных исходных обязательств. Для собственной договорной проблемы или существенной неопределённости без профиля поставщика предел составляет четыре кандидата. Число независимо допущенных равно нулю. Это граница по наблюдаемым метаданным и указанному критерию. Она не устанавливает число неизвестных ошибок в PAY или число подходящих обязательств за пределами этого каталога.

На момент начала текущего продолжения исключение задач предшествующего checkpoint оставляло 165 связанных с архивом групп, 123 PAY-only и предел в 16 проблемных кандидатов. В частности, TH501@A после этого запуска подходит только для открытой проверки штатного разбора. Для конечных точек, затронутых также текущим аудитом привязки записей, исключение использованных им групп оставляет 30 источников, 0 PAY и четыре нерешённых проблемных кандидата. Это анализ чувствительности для открытых проверок текущего этапа.

Узкий публичный holdout можно использовать для вопроса о сохранении корректного допуска в заранее зафиксированной конечной точке. До фиксации нужны проверка пересечений со всеми входами разработки, независимая проверка достаточности фактов, фиксация полного сценария и проверка эффектов в mock-среде. Ни один из найденных кандидатов пока не даёт нового подтверждённого дискреционного случая.

## Воспроизведение

Из корня `cascade-breaker-publication`:

```sh
python3 experiments/payment_controls/native/confirmation/admission.py
python3 experiments/payment_controls/native/confirmation/admission_test.py
```

Скрипт читает наличные metadata receipts и авторские PAY/STOP легитимных сценариев, сохраняя контрольные суммы файлов. Он не запускает FinBot и не читает ответы закрытой серии. Один тест сравнивает пересчитанную опись с сохранённым manifest и проверяет пределы пресетов.
