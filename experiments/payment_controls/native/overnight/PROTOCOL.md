# Ночной открытый пилот маршрутизации до Fraud

Состояние до пилота: Eliza 2,231345304 USD, Jev 0,007708932 USD. Этап разработки: максимум 5 и 2 USD накопительно, общий предел 30 и 10 USD. Для отдельного модельного сравнения резерв Eliza 0,05 USD; общий новый резерв Jev 0,20 USD. Живые исполнители используют прежний совокупный журнал study-live/executor.sqlite с cap 4,8 USD. Другие старые расходы Eliza 0,04699446 USD учтены отдельно. Работа ограничена изолированной учебной SQLite, реальные средства не задействованы.

1. Новые исходные задачи по штатному контракту, вариации группируются. Случаи прежней разработки не становятся независимыми. У двух разметчиков вход без авторских меток; ревью всех расхождений и не менее 20% совпадений. При неполном эталоне сохранять INSUFFICIENT.
2. Решение до первичного расследования: CLOSE_ALLOW завершает только Fraud, CLOSE_STOP требует достаточного основания именно для завершения Fraud с остановкой, DEFER передаёт расследование штатному DeepSeek. Старую авторизацию или изменение счёта подтверждать только доступным первичным свидетельством. Согласованные текущие реквизиты показывают их внутреннюю согласованность. Без доказательства изменения разрешено обычное рассмотрение по штатной политике; когда политика или факты требуют подтвердить изменение и такого источника нет, DEFER. Неразличимые состояния с разной скрытой истиной выделить отдельно; не подменять метку видимого шага итогом по скрытой записи.
3. Сравнить детерминированный код, официальный Jev и DeepSeek Flash на одинаковом исходном пакете и вопросе. Опубликовать сырой выбор модели, ошибки автоматического завершения и избыточную передачу дальше. Критерии и промпт фиксируются до новых ответов. Качество Free-text Fraud — отдельный контраст; контрольные изменения размечать отдельно.
4. Живой открытый пилот: четыре маршрута на одних исходных состояниях, независимая БД, перемешанный фиксированный порядок. До 8 семейных блоков; при ограниченном бюджете запускать только целые сравнимые блоки. Начать с обычного и проблемного сценариев. При дефекте интеграции остановить затронутый вариант, исправить, пометить версии и считать только сопоставимые прогоны; старые попытки входят в стоимость. Отсутствие границы, ошибки транспорта, нарушения полномочий и технические остановки учитывать явно. Публиковать деньги/полное завершение по квитанции, включая корректную остановку, обязательные записи и уведомление. Снижение стоимости рассчитывать вместе с исполнителем и расследованием. Выборка диагностическая; пороги рекомендации 5%, −5 п.п. и меньшая полная стоимость остаются прежними.
5. Ни при каких исходах не расширять квоту, при неопределённом расходе сохранить резерв. При обрыве доступа проводить доступную часть, не заменять официальный Jev другой моделью.

Стадии модельной панели фиксируются раздельно. Исходные пакеты до работы Invoice — диагностический контраст. Для основного сравнения вход непосредственно перед Fraud сохраняется при штатном базовом запуске; этот запуск засчитывается в четыре группы ровно один раз. Парные вызовы моделей на фактических сохранённых входах оцениваются по отдельному слепому эталону. Непосещённые точки остаются в живом знаменателе. Выбор семейных блоков фиксируется до первого модельного результата.

До первого оплаченного вызова согласован узкий CLOSE_STOP для подтверждённого расчёта именно по тому же счёту. Если маршрут может запретить повторный денежный эффект и вернуть управление оркестратору для уведомления, засчитываем такой маршрут только по реальной трассе. Без этого механизма применяется передача штатному Fraud. Номер версии исполняемой реализации фиксируется для каждого этапа. Варианты структурированного ответа — два дополнительных OFF (обычный и смена держателя); сравнить с их исходными OFF по наличию и фактическому содержанию полей.
