# Open overnight native pool

This is a new **open development** pool of 16 native fixture rows grouped into 13 mechanisms. It is not a holdout, a collection of 13 independent real vendors, or confirmation of a false-stop/prevention rate. Every case shares the existing native vendor scaffold; profile/history reuse and near variants are explicit in `groups.json` and `similarity.json`. No old closed 51 outcomes were read or reused. No provider, executor, payment, or external API was called to build the pool.

`fixtures.json` has the exact base `native/fixtures.json` live-loader shape: `id`, `channel`, `profile`, `invoice`, optional `previously_paid`. All rows use isolated `direct` execution. No unsupported setup fields or additional contract/document authority are added. `FINBOT_NATIVE_FIXTURES` may point to this file; select an ID normally. Do not overwrite or append to the old fixtures or campaign outputs.

`build.py` creates each fixture in fresh in-memory SQLite using the actual native repositories, profile seeder and invoice/vendor/risk/paid-history getters. It also invokes the native local TIN-format validator. The already-settled case receives the same completed local transaction/status setup as `native/settled.py`; this performs no transfer. `native_checks.json` records all 16 successful structural checks. The fixed date anchor makes history windows reproducible. Run from the research checkout with `finbot/.venv/bin/python experiments/payment_controls/native/overnight/build.py`.

`panel_inputs.json` is **fixture ID → packet**, ready as a secondary model panel, without rule outputs or labels. `blind_packets.json` contains identical packet values keyed by unrelated blind IDs. Give each independent rater only the blind packets and the identical `source_rule_appendix.md` with its listed native sources. Keep `index.json` (blind/fixture IDs and hashes), `groups.json`, `similarity.json`, and `schedule.json` out of their initial prompt. `input_manifest.json` binds source and output SHA-256 values. Native row IDs are retained for joins; run/owner/profile/family identifiers are excluded from model state.

Every initial panel packet says `stage=native_seed_before_orchestrator_not_observed_pre_fraud`. Its `proposal` is a canonical example, not an observed agent proposal. This **seed** panel is secondary. The primary paired Jev/DeepSeek comparison must use the actual first PRE-Fraud packets reached by the eight same baseline executions, without rerunning the baseline to obtain another sample. Before transferring seed annotations, audit all changed fields and the exact source binding. A baseline that never proposes Fraud has no primary PRE-Fraud packet.

`schedule.json` freezes eight different mechanism groups before ratings or model responses, then shuffles once with seed 2026111701. It covers routine and new-vendor leniency, comparable large history, a new vendor above leniency, a duplicate signal, changed beneficiary, existing high risk, and a prior matching payment. Compare complete live arm blocks in that fixed family order subject to the parent's budget. The 16-row seed panel is not 16 live baselines. Stopping due to budget or technical integration must preserve attempted costs and missing boundaries; do not replace cases based on observed outcomes.

Coverage includes ordinary internally consistent records; the native new-vendor exception; large invoices supported by comparable native history; missing comparative history; amount variance and Invoice review threshold; three duplicate-evidence variants in one group; a bank-holder mismatch/change; an unverified claim that a callback occurred; existing high-risk review context; a pending vendor; the very same paid invoice; and the hard payment ceiling. The tax-unknown variation shares the routine family. These are mechanisms, not author outcome labels.

Important gaps are deliberate and visible: the base loader cannot seed an actual current invoice hold separately from notes, missing TIN/bank fields, an authenticated bank-change receipt, external account ownership, or an independent procurement/approval document. The high-risk profile is **not** an established current unresolved hold. The callback note is **not** independent callback evidence. Thus this pool cannot establish performance on those omitted facts or on a confirmed-bank-change exception. Adding those cases requires a separately implemented and tested native setup extension and a new input freeze. Duplicate similarity is grounds for investigation, not proof that two different invoice IDs are the same obligation. Monetary permission, completeness of Fraud, invoice approval, and end-to-end task completion remain separate axes.

The two independent ratings, route gold, conditional monetary oracle, disagreement review and agreement audit are owned by the independent audit coordinator in its separate audit artifacts. The model provider/question and live adapter are owned by the parent/adapter agent. This builder writes only its input files and manifest; it does not write gold, ratings or model results.
