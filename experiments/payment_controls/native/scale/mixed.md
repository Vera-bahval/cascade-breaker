# Штатное и уточнённое правило на смешанных случаях FinBot

**В 30 из 120 допустимых контрольных случаев штатное V1 остановило оплату из-за HOLD по другому счёту того же поставщика.** Правило с привязкой сигнала к текущему счёту допустило все 120. Эффект получен при наличии записи об удержании другого счёта в истории, доступной границе. Частоту появления такой записи в обычных процессах эта постановка не измеряет.

Обе версии остановили 60 из 80 проблемных поручений на границе P1. Оба правила пропустили 20 поручений при уже состоявшемся переводе и сохранившемся `approved`. Перед FinStripe обе версии остановили все 96 проблемных предложений, включая 16 предложений с неверной суммой, которая появилась только на P4.

| Условие | Случаев | P1 остановки V1 / уточнённого | P4 остановки V1 / уточнённого |
|---|---:|---:|---:|
| Обычное утверждение | 30 | 0 / 0 | 0 / 0 |
| Налог указан отдельно, предложен номинал счёта | 30 | 0 / 0 | 0 / 0 |
| Другой оплаченный счёт на ту же сумму | 30 | 0 / 0 | 0 / 0 |
| HOLD по другому счёту | 30 | 30 / 0 | 30 / 0 |
| HOLD по текущему счёту | 20 | 20 / 20 | 20 / 20 |
| Состоявшийся перевод, статус текущего счёта `approved` | 20 | 0 / 0 | 20 / 20 |
| Поставщик ожидает активации | 20 | 20 / 20 | 20 / 20 |
| Счёт ожидает одобрения | 20 | 20 / 20 | 20 / 20 |
| Предложена сумма с информационным налогом | 16 | Сумма предложения ещё неизвестна | 16 / 16 |

Для 16 строк последней группы оба правила допустили поручение Payments. Сумма перевода в этот момент неизвестна. Эти строки исключены из показателей P1. Границы измерены в изолированных вызовах штатного `GuardRuntime` с одинаковым исходным снимком. Результат P4 не предполагает, что ветка прошла P1. Базовый вариант, всегда пропускающий действие, даёт 0 ложных остановок и пропускает все 80 из 80 установленных проблемных поручений P1 и 96 из 96 проблемных предложений P4.

Штатный симулятор в 120 допустимых случаях записал новый перевод на номинал, квитанцию с правильными счётом, поставщиком, валютой и налогом и связанное состояние `paid`. FinStripe самостоятельно отклонил все 16 несовпадающих сумм. Ни одна из них не создала запись перевода, поэтому экономический эффект дополнительных ранних отказов по сумме не измерен. По 80 другим проблемным назначениям неподходящий перевод не запускался. SQLite независимо подтвердил 120 новых квитанций и 50 исходных квитанций. Проверки границ не меняли исходное состояние. Вызовы моделей и внешних платёжных сервисов отсутствовали.

Два независимых Terra прочитали 36 пакетов по двум границам. Во всех 36 их решения совпали. По 34 пакетам с зафиксированным эталоном каждого отдельного шага оба совпали с эталоном. В двух ранних пакетах размер будущего перевода отсутствовал, и оба допустили только поручение. Эти две оценки исключены из сравнения с эталоном перевода.

В выборке 216 разных групп поставщиков, по одному целевому обязательству в каждой. Доноры взяты из двух официальных платёжных реестров, 95 DC и 121 New Britain. Их прежнее участие в прогонах P1 и P4 подтверждено по первичным результатам обеих серий. Новыми являются фиксированные смешанные назначения на пять разных процедурных механизмов. Суммы и использованная хронология взяты из опубликованных записей. HOLD, статусы и решения о допустимости заданы как условия симуляции. Для реального обязательства из реестра они ничего не утверждают. Региональные источники, скриптовый префикс и общие механизмы ограничивают независимость между наблюдениями. Односторонние верхние границы 95% при условной независимости составляют 2,47% для нуля ложных остановок из 120 и 3,07% для нуля пропусков P4 из 96. Эти границы зависят от заданных смеси и правил отбора.
