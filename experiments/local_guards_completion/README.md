# Завершение архивного исследования FinBot

Для ревью всего PR используйте [маршрут проверки](../../REVIEW.md).
Начать с [общего отчёта](../NO_LLM_REPORT.md). Подробные результаты находятся в
[TABLES.md](TABLES.md), правила оценки в [PROTOCOL.md](PROTOCOL.md), независимая
проверка в [FINAL_AUDIT.md](FINAL_AUDIT.md).

Это ретроспективное сравнение на раскрытом архиве. Оно не заменяет штатных
LLM-агентов FinBot. Новых запросов исследуемым LLM и запусков исполнителя нет.
Локальные LR и CatBoost обучены заново: пять групповых внешних разбиений, всего
десять обучений, без перебора гиперпараметров.

## Что зафиксировано

- `review-batch-*.jsonl.gz`, две серии `labels-*.jsonl` и журналы чтения:
  независимые модельные оценки всех 542 префиксов, до новых предсказаний.
- `adjudicated-*.jsonl`, `extra-adjudicated.jsonl`, `core-corrections.jsonl`:
  разрешение разногласий и проверка найденных общих ошибок. Это модельная
  разметка, а не независимый человеческий эталон.
- `labels.jsonl`, `labels-freeze.json`: отдельные оценки процедур, содержания
  платежа и полного действия. Исходные авторские категории сохранены.
- `source-targets.jsonl`, [SOURCE_TARGETS.md](SOURCE_TARGETS.md): исходные
  ожидания бенчмарка; 310 `not_defined` не превращены в выдуманный бинарный
  эталон. Новая оценка действий хранится отдельно.
- `captured-policies.json.gz`, `records.jsonl.gz`, `records-manifest.json`:
  исторические инструкции и входы до проверяемого действия. Восстановлены
  потерянные связи сессий и ролей; финансовые значения не заменялись.
- `code-freeze.json`, `results/prediction-freeze.json`: код и источники,
  допущенные до массового вычисления, и хеши ответов. `SOURCE_ADMISSION.md`
  сохраняет независимый допуск именно перед вычислением.
- `results/`: новые ответы правил и ранних проверок, 43 080 измерений времени.
  `ml-results/`: разбиения, десять моделей, OOF-вероятности, фиксированная сетка
  порогов и 1 800 измерений. [SCALER_AUDIT.md](SCALER_AUDIT.md) объясняет
  проверенное численное предупреждение sklearn.
- `results-summary.json`: машинные таблицы с хешами входов оценщика;
  [COST_AUDIT.md](COST_AUDIT.md) и `cost-audit.json`: сверка исторических расходов.

Прежние данные, разметка и предсказания в соседних каталогах сохранены. Новая
проверка является развитием общего архивного checker; её базовый и текущий
варианты различаются подготовкой исходных/актуальных значений. Это не два
независимых алгоритма и не полный перенос старого v4.3.

## Проверить сохранённые результаты

Команды выполняются из корня этого checkout в Python-окружении с numpy, sklearn,
CatBoost, joblib и matplotlib. Версии зафиксированы в `code-freeze.json`.

```sh
python -B -m unittest discover -s experiments/local_guards_completion -t .
python -B -m experiments.local_guards_completion.evaluate
python -B -m experiments.local_guards_completion.outcome_timing
python -B -m experiments.local_guards_completion.render
```

Расчёт `outcome_timing` группирует сохранённые времена 176 задач по правильности решения и успешности завершения, без новых исполнений.

Оценщик читает сохранённые предсказания и проверяет их квитанции; он не вызывает
модели. Рендерер обновляет общий отчёт, подробные таблицы и PNG/SVG-график. Старый
вход `local_guards_archive_profile.update_report` перенаправлен в этот рендерер,
чтобы повторная генерация не возвращала устаревшие выводы.

Точные квитанции содержат абсолютные пути исходного checkout. Для побайтовой
проверки оценщика нужен тот же путь; перенос checkout требует явного изменения
маршрутизации источников и новой квитанции, а не замены исторических хешей.

## Повторить вычисление

Это отдельный эксперимент. Сначала проверить исходные архивы по манифестам,
исторические политики, связи и замороженную разметку; затем сохранить новый
допуск кода. Исходные tar-архивы находятся вне этого checkout, их наличие нужно
для повторного извлечения инструкций и ранних событий. Подготовленные входы и
ответы опубликованы здесь для проверки таблиц без этих архивов.

Порядок исполнения: `run` для новых ответов правил, `ml` для десяти обучений,
`run --benchmark`, затем `ml_benchmark`, затем `evaluate` и `render`. Для новых
прогонов использовать отдельные выходные каталоги. Существующие квитанции,
модели, разметку и предсказания не перезаписывать; скрипты вычисления отклоняют
такую попытку. Замеры правил и ML выполнять последовательно без конкурирующей
нагрузки. Загрузка моделей, начальная сборка свидетельств и диагностика
исключены из рабочего таймера; учёт полного времени 176 задач описан в отчёте.

Групповое разделение ограничивает утечку между FIT/CAL/test, но ранее раскрытый
архив от этого не становится закрытым тестом. Почти сплошной BLOCK по полному
эталону преимущественно отражает обязательную процедуру TaxCalc. Его нельзя
выдавать за точность антифрода или полезность для обычных задач.
