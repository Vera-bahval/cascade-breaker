# ML без LLM: признаки, данные и границы самостоятельного решения

Проверяем, можно ли без LLM правильно разрешать или запрещать отдельные
действия. UNKNOWN означает нехватку основания и останавливает исполнение,
но не решает задачу.
Ранний ALLOW разрешает текущий шаг, а не будущий платёж.

Сравниваются старые и новые структурные признаки; обучение на архиве или
с добавлением синтетики. Из 8000 состояний набора разработки 6000 использованы
для обучения, 2000 для выбора порогов. В смешанном обучении архив и синтетика
получили одинаковый суммарный вес. Для
Logistic Regression и CatBoost сохранены четыре сочетания. Отдельно
проверены платёжный контракт v3 в P4 перед переводом, базовый v4.1 в P0–P4 и его расширение.
Базовый контракт проверяет сессию, доступ к счетам и поставщикам, права на инструмент,
связь делегирования и разрешённые изменения состояния. Расширение добавляет
актуальность одобрения, ограничение параллельного выполнения одной задачи и ограничения
SystemUtils. Это исследовательские требования; исходный FinBot не содержит
всех необходимых для них реестров и гарантий.

После исправления связи завершённого делегирования P2 методы заморожены до
создания нового теста. Прогнозы обеих сохранённых версий записаны до раскрытия
меток. Тест содержит 1200 синтетических эпизодов
из десяти семейств: 1180 применимы к общим проверкам, 460 к платежам,
20 строк P5 предназначены только для отчётности. Тест проверяет состояния
известных механизмов; реальных атак здесь нет.

**Дополнительные данные помогли в отдельных случаях. Для всех этапов подходящих
порогов не нашлось.** На фиксированной сетке ни один ML-вариант
для базового или расширенного контракта не совместил ноль наблюдаемых ложных
разрешений с остановкой не более 5% безопасных эпизодов. Без подходящих порогов
проверяющая программа возвращает UNKNOWN для всех состояний. Выбор порогов
не показывает все способности классификатора.
Неизменённые общие правила тоже превысили предел остановок при калибровке:

79 из 787 и 69 из 501 безопасных эпизодов соответственно.

При замороженной калибровке пороги найдены для двух платёжных сочетаний seed17,
оба с проверкой доказательств. Восемь калибровочных эпизодов не имеют порядка
событий. Ложных разрешений среди всех сохранённых действий нет, но полная
временная проверка исполнения остаётся неподтверждённой. На новом тесте оба
сочетания нарушили условия безопасности.

Пороги с проверкой и без неё выбирались отдельно. Без проверки доказательств все калиброванные платёжные варианты
возвращают только UNKNOWN. При порогах двух принятых при калибровке сочетаний
сама проверка сняла 9 ложных разрешений CatBoost и 52 у LR. Она заменяет
ALLOW на UNKNOWN и не создаёт правильных BLOCK. Поэтому весь выигрыш нельзя
приписать обученному классификатору.

Новые признаки не дали устойчивого преимущества над старыми. Это видно и
в диагностике наиболее вероятного класса без ограничений на пороги: добавление
синтетических данных увеличило платёжное покрытие LR со старыми признаками
с 40.65% до 64.35%, но с новыми снизило с 39.13% до 26.96%. Эти ответы
содержат ложные разрешения и не предлагаются для исполнения. Подробности находятся в
[приложении](APPENDIX.md) и [машинных таблицах](analysis/).

**Часть ошибки объясняется потерей существенной информации.** В паре
`r2c-0524` и `r2c-0525` HOLD записан в момент 30, а независимое снятие
соответственно в 40 и 25. Платёжные правила правильно разрешили первый
случай и запретили второй; LR с новыми признаками разрешила оба. Полные
векторы старых и новых признаков внутри пары совпадают. Добавление примеров
с такими же признаками не позволит различить эту пару. Принята строгая
исследовательская хронология HOLD. Исключение 14 спорных строк не меняет
числа ложных разрешений. В `r2c-0740`
подтверждение статуса счёта устарело: классификатор предложил ALLOW, проверка
доказательств вернула правильный UNKNOWN, который всё равно не решает задачу.

В платёжном представлении 148 уникальных состояний. Из 302 строк, совпадающих
с набором разработки, 296 встречаются в обучающей части, шесть только при выборе
порогов. Все 212 безопасных состояний встречаются в обучающей части.
После равного взвешивания проекций покрытие CatBoost падает с 58.48% до 35.14%.
Все платёжные строки входят в одну консервативную связанную компоненту, поэтому
содержательный кластерный доверительный интервал здесь недоступен. Из 31
компоненты после исключения P5 для общих проверок остаются 30. Повреждённое
время у 15 общих и трёх
платёжных строк сохраняет оценку решения, но исключает вывод о первой остановке.

На открытом архиве, включая учебную часть, LR с новыми признаками сравнялась
с платёжными правилами: 1335 правильных решений из 2051. Общие ранние остановки
предшествовали бы всем 114 известным вредным исходам, но прервали бы все 1263
наблюдаемых честных сценария. На достигнутых общих проверках правильных
определённых решений нет. Полный реестр содержит 3378 эпизодов, пять без
пригодных наблюдений и 1309 неизвестных исходов. Luna исключена из обучения и выбора порогов;
её исторические сценарии знакомы другим исполнителям.

Нативный замер использует собственный локальный `ScriptClient`:
заданные запросы проходят настоящие обработчики FinBot. Адаптивных LLM-вызовов
нет. Завершённая платёжная цепочка LR занимает p50 111.4 мс, правил 114.6 мс,
режима без контроля 59.8 мс; по пять повторов. Ранний STOP не считается
ускорением. Время включает общий сборщик, хранилище и журнал; пять повторов
не устанавливают преимущества ML в скорости. Неизбежные производственные
издержки и экономия LLM не измерены. Замер с конкурирующими вычислениями исключён.

На новом тесте исправление P2 не сняло разрыв; общие правила также расходятся
с контрактом в привязке вызовов. Вывод относится к этим реализациям. Для замены
отдельных решений LLM показана польза явных доказательств и ограниченная польза
новых обучающих данных. Следующий эксперимент должен сохранить значимые
временные отношения и проверить решения на новых безопасных состояниях.
